## 2. 目標架構

```
src/core/GameCore.js          ← 唯一組裝點
  ├─ 渲染   renderer / camera / composer（後製鏈分級）
  ├─ 世界   Environment（晝夜天氣）/ quality / fog / vista
  ├─ 玩家   角色模型 / Controller / Progression / vitals / loadout
  ├─ UI     HUD / ESC / dialogue / questlog / skillpanel /
  │         minimap / worldmap / 時刻與地名顯示
  ├─ 系統   combat / mobcore / hazard / portal / riftPortal / signpost
  └─ 迴圈   單一 animate()，子系統註冊 update 回呼
```

**目標的地圖檔開頭**：
```js
import { GameCore } from '../../src/core/GameCore.js';

const core = await GameCore.boot({ mapId: 'sunflower', postFX: 'full' });
const { scene, world, ctx } = core;
// —— 以下才是這張圖獨有的：地形、建築、裝飾、怪、NPC、傳送點 ——
core.registerUpdate((dt, t) => { /* 本圖獨有的每幀邏輯 */ });
core.start();
```
樣板從 120 行降到 5 行。

## 3. 分階段實作

### 階段 A：建立 GameCore，只讓一張圖用
1. `src/core/GameCore.js`，把 sunflower.js 的樣板抽成
   `GameCore.boot()` / `registerUpdate()` / `start()`。
2. 提供：renderer/camera/scene/world、Environment、quality、
   玩家全套、HUD＋ESC、resize、單一 animate 迴圈。
3. sunflower.js 改用它，**行為必須完全不變**。
4. 不要碰其他圖。

### 階段 B：後製鏈分級
1. main.js 的 GTAO/Bloom/SMAA/ShaderPass/OutputPass 移進 GameCore，
   做成 `postFX: 'full' | 'basic' | 'off'`，與 quality 三檔連動。
2. sunflower 先切 full，截圖 A/B 與效能數據給我決定其他圖跟不跟進。
> **注意**：這一項與《材質與畫質升級書》第 4.1 節是同一件事，做一次即可。

### 階段 C：新模組收編（v2 重點）
`vista` / `minimap` / `worldmap` / `signpost` 目前是各圖自己接。
收進 GameCore，改成由 mapRegistry 資料驅動、自動掛載：

| 模組 | 現況 | 收編後 |
|---|---|---|
| vista | 各圖自己算 radius／gaps／heightAt | GameCore 讀 mapRegistry 的 playSize 與 connections 自動算：半徑＝圖半徑＋80，gaps＝各傳送點方向 |
| minimap | 各圖自己傳 bounds/paths/portals | GameCore 從已建好的 PathNet 與 portal 清單自動組 |
| worldmap | 各圖自己傳 current/isBlocked | GameCore 用 mapId 與 mapRegistry 的 built 自動判定 |
| signpost | 各圖自己在傳送點旁擺 | 建立傳送點時自動生成，文字取目的地圖名 |

**做法**：GameCore 內部維護一份「本圖傳送點清單」，
`core.addPortal({ to, x, z })` 一次搞定：光點＋道標＋minimap 圖示＋
vista 缺口＋觸發判定。地圖檔不用再各接四次。

### 階段 D：功能孤島清零
盤點並統一（先產出「哪張圖缺哪個」的表再逐項收）：

| 功能 | 現況 | 目標 |
|---|---|---|
| 右上角時刻顯示 | 只有神社 | 全圖標配 |
| 地名顯示 | 部分 | 全圖，讀 mapRegistry |
| 按鍵提示列內容 | 各圖手寫（神社漏了 K） | GameCore 依實際掛載的系統自動生成 |
| 後製鏈 | 只有神社 | 依 postFX 分級 |
| ZoneTracker | 只有神社 | 有子地帶的圖都能用 |
| dialogue / questlog | 各圖自己接 | 有 NPC 就自動有 |
| SceneEditor | 各圖 import | GameCore 統一，dev 才載 |
| debug handle | 部分 | 統一 `window.debug`（tp/pos/setHour…），給 /playtest 用 |

### 階段 E：其餘六張圖遷移
一次一張，每張跑 `/playtest <圖>` 對照重構前後，確認行為不變才進下一張。
順序：kourindou → eientei → namelessHill → bamboo → trail → village → main.js（神社最後，獨有東西最多）。

### 階段 F：擴充插槽
```js
GameCore.use(SaveSystem);    // 存檔（目前散在 localStorage）
GameCore.use(AudioSystem);   // 環境音／腳步（見下方第 5 章）
```
統一介面 `{ init(core), update(dt,t), dispose() }`。

## 4. 存檔與跨圖狀態

目前跨圖靠 localStorage 手動存取、散在各處。GameCore 統一：
```js
core.state   // HP/MP/等級/任務進度/已探索地圖
core.save()  // 換圖前自動
core.load()  // boot 時自動
```
Schema 集中一處。之後若做 SPA，這層變成純記憶體傳遞，介面不用改。

## 5. 後續六大項（GameCore 完成後的路線圖）

依投報率排，全部都應該做成 GameCore 的插槽或子系統，**不要各圖各接**。

### 5.1 音效補齊（缺口，不是從零）
**現況**：`src/fx/slash.js` 的 `SlashAudio` 已用 WebAudio 合成出招音
（破空＝白噪聲過帶通下滑、火焰＝低通噪音、重擊加低頻 thump），
做得很紮實。**缺的是環境層與回饋層**：

1. `AudioSystem` 插槽：統一 AudioContext（現在是 SlashAudio 自己開的，
   收編進來避免多個 context）、主音量／分類音量、ESC 選單加音量設定。
2. **環境音**（全部程序合成，不引入音檔，維持專案原則）：
   - 風：低通白噪聲 ＋ 緩慢 LFO 調變增益，強度接 weather.js
   - 竹葉／樹葉：高頻帶通噪聲短爆發，隨風強度觸發密度
   - 水：河與湖用多層帶通噪聲疊出流水感，音量隨玩家與水體距離
   - 人里環境：低頻人聲嗡鳴（多個窄帶正弦疊 detune）＋偶發市集敲擊
   - 每張圖的環境音組態放進 mapRegistry，GameCore 自動掛
3. **腳步聲**：依 groundHeight 所在材質（草／土／石板／木橋／水淺灘）
   換合成參數，跑步/走路不同間隔。這一項對「人在世界裡」的感受
   幫助極大，成本很低。
4. **UI 與回饋音**：開關面板、對話推進、任務完成、受擊、拾取。
5. **BGM**：這是唯一必須面對「要不要外部音檔」的地方。
   程序生成的 BGM 很難好聽。建議先做「無 BGM 但環境音紮實」，
   BGM 留到最後單獨決策。

### 5.2 戰鬥手感細修（缺口，不是從零）
**現況**：`combat.js` 已有 hitstop（0.07/0.1/0.14 依普攻/暴擊/終結技）、
受擊紅屏與震動；`src/fx/` 有 slash / dragon / embers。基礎很好。
**補的是細節**：
1. 命中回饋分層：目前 hitstop 有了，補**擊中瞬間的白閃**（被擊中者
   材質短暫替換成純白 0.05s）——最便宜的「打到了」的訊號。
2. 擊退與硬直：怪被擊中要有位移與動作中斷，現在可能只是扣血。
3. 傷害數字：彈跳、暴擊放大變色、多段快速命中要錯開位置不要疊字。
4. 斬擊軌跡殘影：拖尾在收招後短暫殘留。
5. 鏡頭：終結技時輕微推近＋降 FOV；連段命中時鏡頭微幅跟隨抖動
   （幅度要小，太大會暈）。
6. **鎖定目標（lock-on）**：動作遊戲的基本盤，現在若沒有，
   多怪環境下手感會很差。

### 5.3 主線劇情架構（暫緩，等使用者回頭處理）
使用者已有 15000 行的既有創作文本作為素材，核心主題與關鍵橋段
（芙蘭線、彼岸審判、蕾米震怒、緣一求休息）已成形。
**待決策**：外界敵人的定位、非東方角色是否保留、結局輪廓。
決定後再寫，因為它會反過來影響地圖與 Boss 設計。

### 5.4 美術聖經（art bible）
18 張圖若各自決定配色與比例，最後會像 18 個人做的。需要定死：
1. **色票**：和風主色群、各地區的 accent（config.js 已有雛形，系統化）
2. **建築比例規則**：柱徑/樑高/屋簷出挑/門窗尺寸的相對比例，
   讓所有和風建築一眼是同一個世界的
3. **時段色調表**：晨/晝/昏/夜四段，各段的天空色、霧色、光色、
   陰影色（現在 daycycle 有做，但沒有文件化成規則）
4. **地區視覺識別**：每張圖一句話的視覺主張（「魔法之森＝陽光照不進來
   的濕綠」），蓋圖時對照
5. **裝飾密度基準**：以人間之里為 1.0，各類地圖的相對密度

### 5.5 Boss 戰設計書
紅魔館是第一座 Boss 地城。Boss 戰與雜魚戰是兩套設計：
1. **階段轉換**：血量門檻切換招式組，配合場地變化
2. **彈幕致敬**：東方原作是彈幕遊戲，Boss 應該有符卡式的
   彈幕階段——但這是 3D 動作遊戲，彈幕要能用走位/格擋/斬擊應對，
   不是照抄 2D 判定
3. **破綻窗口**：大招後的硬直＝玩家的輸出機會，這是動作遊戲的節奏核心
4. **學習曲線**：第一次必死不可以，但第三次要能過
5. 先做一隻（建議紅美鈴當「守門型中 Boss」，比蕾米莉亞單純），
   驗證框架再擴充

### 5.6 新手引導與首次體驗
玩家前 5 分鐘決定他會不會繼續玩。目前是直接丟進神社。
1. **開場**：緣一轉生的瞬間做成可玩的過場（睜眼、起身、第一次呼吸），
   而不是直接控制
2. **漸進教學**：移動→視角→互動（第一個 NPC）→戰鬥（第一隻弱怪）
   →技能→地圖，一次教一件，用場景引導而非彈窗
3. **第一個目標**：五分鐘內給玩家一個明確的去處（例如靈夢叫他去人里），
   避免「不知道要幹嘛」
4. 這一項建議等劇情架構定案後做，因為開場就是劇情的第一幕
