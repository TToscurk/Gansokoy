# 產生器領域模型與架構決策

這份文件只保留目前仍有效的詞彙、邊界與 ADR。完整的討論與演變歷史在
`archive/domain-model-full-history-2026-08-11.md`；除非要追查決策爭議，
日常工作不要讀 archive。

## 核心詞彙

### 地形與取樣

- **BankHeight**：河岸或水體邊緣的目標高度，不等於任意地表高度。
- **GroundHeight**：指定世界座標的可站立地表高度。
- **GroundSample**：高度、法線、材質／遮罩等地表查詢結果；呼叫端不應猜測
  generator 的內部公式。
- **Carve**：從既有地形或遮罩中挖除一個區域，例如河道、池塘或道路。
- **Footprint**：物件實際占用的平面範圍。放置、碰撞與淨空判定都應使用量測
  後的 footprint，不以名稱或肉眼估算尺寸。

### 土地與交通

- **Parcel**：可被建築、庭院或設施認領的土地單元。認領資料應保留用途與來源
  標籤，方便碰撞診斷。
- **Zone**：土地用途與密度規則；不是另一份手工座標表。
- **PathNet**：道路、巷道、橋與入口的連通關係。路網是放置規則的輸入，不應
  從已生成的建築反推。
- **Frontage**：面向道路的可用立面／入口側。必須同時檢查面向道路與背向基地
  兩側的淨空。

### 水體、建築與道具

- **WaterBody**：河、池、溝渠共用的查詢概念，包括水面、岸線、深度與排除區。
  目前實作可以分散在不同模組，但使用者不應自行重算水域邊界。
- **Module / AssetFamily**：可組裝或替換的資產單位與同族變體。實際尺寸與立面
  資料以 `godot/assets/blender/town_modules.json` 為準；其唯一寫入者是
  `godot/assets/blender/make_town.py`。
- **FacingAxis**：模型的正面軸。町家與可朝向資產統一以本地 `+X` 為正面；若有
  例外必須在資產資料中明示。
- **ScatterRule**：植被、雜物與生態物件的密度、排除區、坡度和隨機規則。
- **AABB / OBB**：AABB 用於快速粗篩；旋轉物件的實際重疊與淨空要用 OBB 或等價
  的方向性判定。

## 現行模組邊界

- `godot/tools/gen_town.gd` 是人里 generator 的組裝入口，持有執行順序、共享狀態
  與 deterministic RNG。不要讓子模組各自建立 RNG，也不要改變抽樣順序。
- `godot/tools/town/*.gd` 承擔街區、密度、地標、市場、植被、碰撞與批次等具體
  責任；模組透過明確參數或 callback 取得主檔狀態。
- 地圖 generator 仍使用 GDScript。資料檔只承載適合資料化的規格，不把整張地圖
  退化成一個巨大 JSON。
- 生成出的 `.tscn` 才是驗證對象。檢查工具不得只根據 generator 原始碼推測結果。
- 穩定輸出雜湊、節點數與驗證結果用來阻止結構重構造成輸出漂移；涉及 RNG 的
  搬移必須逐刀比較。

## 架構決策摘要

| ADR | 現行決定 |
|---|---|
| **ADR-001** | 在新功能真正需要時從邊界抽出領域概念；不為了形式統一而重寫所有舊地圖。 |
| **ADR-002** | 地圖保留 GDScript generator；只把純規格與資產量測資料化。 |
| **ADR-003** | `check_map.gd` 與 `walk_test.gd` 都保留：前者查結構／碰撞，後者查實際可行走輸出。 |
| **ADR-004** | 材質與視覺退化必須用固定視角 render evidence 加 Human Art Review 判定；結構檢查不能代替審圖。 |
| **ADR-005** | 角色優先的早期方向驗證已完成，屬歷史決策；沒有額外的現行實作規則。 |
| **ADR-006** | 專案終點是可遊玩的遊戲，不是只有可觀看的場景。系統設計要能承接互動與玩法。 |
| **ADR-007** | 先把少數核心地點做深、做可玩，再擴張地圖數量。 |
| **ADR-008** | 原生地圖使用 `own_colliders`；只有 Terrain 或明示 `needs_trimesh` 的網格才補 trimesh 碰撞。 |
| **ADR-009** | 舊角色比例規格已被 ADR-011 取代。 |
| **ADR-010** | 早期有機街路提案已回滾；不要把當時的道路數字當成現況。 |
| **ADR-011** | 現行角色約 4–5 頭身，不使用骨架；頭、髮、衣裝等維持可獨立替換的部件。 |
| **ADR-012** | 場景密度由環境、建築、道具與角色共同形成；不能只靠增加單一類物件補空。 |
| **ADR-013** | 人里街路回滾已定案；現行道路與河道結構以 `gen_town.gd` 及人里規格文件為準。 |
| **ADR-014** | 端點定義的樑柱／連接幾何使用 `Lib.strut` 等共用工具，不手算旋轉與中點。 |
| **ADR-015** | 重複座標與門檻值要提升成有名稱的規則或常數，避免隱藏魔法數字。 |
| **ADR-016** | 地圖與資產使用固定相機、固定檢查方向及 Human Art Review，讓前後結果可比較。 |
| **ADR-017** | 要存入 PackedScene 的節點必須有合法 `owner`（通常是場景 root）；generator 遇到無效 owner 應直接報錯。 |
| **ADR-018** | Frontage 要檢查雙向淨空；Parcel claim 必須附帶可診斷的用途／來源標籤。 |
| **ADR-019** | terrain mask 使用 RGBA 通道；A 通道代表 compacted earth，新增用途不得默默改寫既有語意。 |

## 修改 generator 時的硬條件

1. 不改 RNG ownership、呼叫順序或 procedural generation 的階段順序。
2. 不以重構名義改資產選擇、座標、數量、碰撞、道路、地標或視覺輸出。
3. 每次只搬一個可驗證責任；前後比較穩定輸出雜湊、節點數及既有 validation。
4. 碰到 footprint、frontage、水域或地面高度時，使用既有查詢契約，不複製公式。
5. 新領域詞彙或跨模組不變量才寫入本文件；施工日誌與逐輪結果放 commit，不回填成長篇歷史。
