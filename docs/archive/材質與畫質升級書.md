# 《緣一・幻想鄉》材質與畫質升級書 —— 風格化 PBR 路線
> 基於 main（81aac4e）實測。與品質升級書（地形/UI）、共用系統整合書（GameCore）分開跑。
> 路線：**角色維持卡通描邊，環境走寫實質感**（原神／薩爾達的做法）。

---

## 0. 現況修正：你比想像中更接近目標

實測程式碼：
- **MeshStandardMaterial 25 處、MeshToonMaterial 只有 5 處**——環境早就是 PBR 材質，
  Toon 主要用在角色上。方向已經對了。
- 神社已有完整 canvas 程序化貼圖庫（`TEX.wood/stone/masonry/roof/shoji/lacquer/ofuda`），
  且 roughness 有分別調校（石 0.95、木 0.85、漆 0.48）。
- 已有 IBL（PMREM 環境光）、ACESFilmic 色調映射、GTAO、Bloom、SMAA。

**所以問題不是「引擎不行」也不是「要換材質系統」，是三個具體缺口：**

| 缺口 | 症狀 | 難度 |
|---|---|---|
| 沒有法線貼圖（normalMap） | 表面平滑如貼紙，木頭沒有木紋起伏、石牆沒有磚縫深度 | 低 |
| 沒有粗糙度貼圖（roughnessMap） | 同一個表面從頭到尾一樣亮，塑膠感 | 低 |
| 地形沒有貼圖（只有頂點色） | 大面積地面最扁平，也最佔畫面 | 中 |
| 後製鏈只有神社有 | 同款遊戲兩種畫質標準 | 低（已列在整合書階段 B） |

## 1. 核心技術：從既有 canvas 貼圖自動生成法線貼圖

不需要外部資產、不破壞「純瀏覽器生成」原則。做法：把現有 `TEX.*`
畫出來的灰階明暗當成高度場，用 Sobel 算子求斜率，轉成法線貼圖。

新增 `src/world/texgen.js`：

```js
/** 從既有 CanvasTexture 的亮度生成法線貼圖 */
export function normalFromCanvas(canvas, strength = 1.0) { … }
/** 從亮度生成粗糙度貼圖（暗處通常較粗糙，可反轉） */
export function roughnessFromCanvas(canvas, { min, max, invert }) { … }
```

改造 `makeTexture()`，讓它同時回傳三張：
```js
const { map, normalMap, roughnessMap } = makeMaterialMaps(size, draw, rx, ry, {
  normalStrength: 1.2, roughRange: [0.6, 0.95]
});
```
然後材質定義從：
```js
MAT.stone = new THREE.MeshStandardMaterial({ map: TEX.stone(1,1), roughness: 0.95, … });
```
變成：
```js
MAT.stone = new THREE.MeshStandardMaterial({ ...TEX.stone(1,1), color: '#cfcabc' });
```

**這一項是整份升級書投報率最高的**：不加任何三角形、不下載任何檔案，
所有既有建築立刻有表面起伏。

## 2. 提升 canvas 貼圖本身的細節密度

現有 `noise()` 只做逐像素隨機雜訊（白噪音），質感偏「顆粒」不像「材質」。
升級成分層 noise：

1. 實作 value noise / fBm（多層八度疊加），這是木紋、石紋、雲紋的基礎。
2. 各材質的畫法升級：
   - **木**：fBm 拉長成條狀年輪 ＋ 節疤（隨機圓形擾動）＋ 縱向細裂紋
   - **石**：fBm 斑駁 ＋ Worley/細胞噪音做顆粒感 ＋ 邊角磨損變亮
   - **磚石牆**：磚縫做深（法線貼圖會吃這個）＋ 每塊磚色調微差
   - **瓦**：瓦片弧面的明暗漸層（法線貼圖轉出來就有立體瓦楞）＋ 苔痕
   - **障子紙**：纖維紋理 ＋ 透光不均
3. 貼圖尺寸：目前多半偏小，關鍵材質（地面、主建築牆面）提到 512 或 1024，
   次要的維持——用 `renderer.info.memory.textures` 監控總量。

## 3. 地形三平面貼圖（triplanar）—— 畫面佔比最大的一塊

**問題**：地形是程序生成的高度場，沒有合理 UV，所以只用了頂點色，
是全畫面最扁平的部分；直接貼平面 UV 的話陡坡會拉伸糊掉。

**做法**：寫一個 triplanar shader（`onBeforeCompile` 注入
MeshStandardMaterial，不用自己重寫整套光照）：
- 從三個軸向各採樣一次，用法線權重混合——陡坡不拉伸
- 依高度與坡度混合材質：低地草地 → 泥土 → 岩石（坡度陡的自動露岩）
- 三張材質各自帶 normalMap，混合後地面就有真實起伏感
- 路面（PathNet 沿線）用 decal 或第四層混合，不要靠改頂點色

**注意**：triplanar 每像素採樣三次，成本較高。低畫質檔位退回
單軸 UV 或純頂點色（跟 quality.js 三檔連動）。

## 4. 光照與後製的精緻化

1. **後製鏈全圖統一**（＝整合書階段 B，兩份文件同一件事，做一次即可）。
2. **對比度來自陰影而非亮度**：目前整體偏亮平。GTAO 強度可以再加，
   並確認接觸陰影（物件與地面接觸處的暗角）有出來——這是「物件放在
   地上」而不是「浮在地上」的關鍵。
3. **環境光遮蔽貼圖（aoMap）**：建築內凹處（屋簷下、柱腳）手動給 AO
   或從 canvas 生成，成本低於 GTAO 但效果互補。
4. **色調分級（LUT）**：ACESFilmic 之後加一層 LUT，讓不同地區有
   明確色調個性（魔法之森偏冷綠、太陽花田偏暖）——比只調 fog 色深刻得多。
5. **各向異性過濾**已經開到 8，可以確認低階裝置是否需要降。

## 5. 執行順序與 A/B 驗證流程

**強制流程：每一項都先在博麗神社（材質最豐富）做，截圖 A/B 給我看過再推其他圖。**

| 順序 | 項目 | 預期效果 | 風險 |
|---|---|---|---|
| 1 | 法線貼圖自動生成（第 1 章） | 最大提升，所有建築立刻有質感 | 低；strength 過大會像浮雕，需調 |
| 2 | 後製鏈全圖統一（第 4.1） | 消除畫質雙標 | 低；低階機效能要測 |
| 3 | canvas 貼圖細節升級（第 2 章） | 材質從「色塊」變「表面」 | 低 |
| 4 | 粗糙度貼圖（第 1 章附帶） | 消除塑膠感 | 低 |
| 5 | 地形 triplanar（第 3 章） | 畫面佔比最大的一塊 | 中；shader 注入要小心與現有 fog/toon 衝突 |
| 6 | LUT 色調分級（第 4.4） | 地區個性 | 低 |
| 7 | AO 貼圖（第 4.3） | 細節收尾 | 低 |

## 6. 明確不做的事（避免走錯路）

- **不要讓角色寫實化**：角色是 box/cylinder 程序生成、動畫比例，
  PBR 光照會把「低模」從風格暴露成「沒做完」。角色維持 Toon ＋ 描邊。
- **不要引入外部貼圖檔**（ambientCG 等）：質感跳躍確實最大，但會破壞
  「純瀏覽器生成、無資產下載」的專案原則，且要處理 KTX2 壓縮與 VRAM。
  先把程序化生成的天花板做滿，真的不夠再談。
- **不要半調子混搭**：同類物件要換就整類換（所有建築、所有地形），
  不要一棟一棟改，混搭比全卡通更糟。
- **不要為了質感犧牲明亮感**：原始美術方向是明亮卡通世界，
  加了法線與粗糙度之後如果整體變暗沉，是調過頭了——
  目標是「不扁平」，不是「不明亮」。
