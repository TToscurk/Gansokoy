## 2. PHASE 1 做了什麼

新檔 `godot/assets/blender/make_machiya.py`，產 `machiya_f_a`。
`make_town.py` 的模組迴圈對 `PROTO = {"machiya_f_a"}` 改呼叫它 ——
**manifest 仍由 `make_town.py` 統一寫出**（一份 manifest 一個寫入者，
兩邊各寫一份遲早對不上）。

### 真壁造：軸組先立，漆喰填進去

```
土台 150×150 → 柱 150×150（四角通し柱 + 正背面管柱 + 側面管柱）
            → 貫 105×30（兩道，兩面各凸 30mm）
            → 内法長押 130×30
            → 桁 180×180（頂面齊屋面起點）
```

漆喰是**逐格嵌板**、比柱面**內縮 25mm**。那 25mm 的落差就是真壁造在遠景
唯一讀得出來的東西 —— 牆不再是一個連續量體，柱是真的比牆凸出來，
陰影線是**幾何**不是貼圖。

### 立面（四開間，刻意不對稱）

```
bay0 出格子（凸 0.34m 的盒子：底板＋持ち送り＋兩側板＋障子背板＋直櫺＋上枠）
bay1 連子格子（腰板＋障子＋直櫺＋上下框）
bay2 大戶口（兩片板戶＋橫桟＋敷居）＋ 庇
bay3 連子格子
```

### 庇：完整構件

腕木 → 前桁 → 垂木（看得到的椽）→ 野地（含厚度）→ 鼻隠し → 軒裏（仰視面，
木色不是瓦色）→ 丸瓦。出簷 0.95m、坡度 17°。

### 屋頂：一組構件

野地（厚 0.16）→ 鼻隠し → 軒裏 → 垂木（出簷段，18 根）→ 丸瓦（本瓦葺きの
縱向半圓，每側 26 條）→ 軒瓦（簷端巴瓦）→ 妻壁（**漆喰**）→ 破風板 →
懸魚 → 棟（熨斗瓦 + 冠瓦）。

## 3. 三個在製作中實際炸出來、修掉的問題

1. **總高 4.78 ≠ 規格 4.50。**
   舊版的棟只有一根 0.14 的方條，新版是熨斗＋冠瓦兩層 0.26。屋身反推公式
   扣的還是 0.14，差的 0.28 全部往上長。天際線的階梯是使用者定案過的，
   prototype 不許順手改掉 → **屋身讓棟**，內法高同時收到 1.72。

2. **桁戳穿屋面。**
   第一版把桁擺成「坐在 z_wall 上往上長」，而屋面在牆線的高度就是 z_wall
   —— 桁往上凸 0.18 直接穿出屋頂，正是規格明列的禁項
   `roof intersecting wall`。改成**桁頂面齊 z_wall**。
   同一個理由拿掉了小屋梁：它架在兩道桁之間、擺在那個高度一定穿出屋面，
   而平入切妻的妻側看到的是妻壁與破風板，梁端本來就被遮住。

3. **Godot 的 glTF 匯入快取不會自己更新。**
   換成六材質的 glb 之後，`semantic_mesh()` 讀回來仍然是 **1 個 surface**
   —— 讀到的是 `.godot/imported/` 裡舊的 `.scn`。要先
   `rm .godot/imported/machiya_f_a.glb-*` 再 `godot --headless --import`。
   **這條要寫進流程**：模組的材質結構改變時，光重跑 Blender 不夠。

## 4. 材質身分怎麼活著走完管線

```
Blender 六個材質（WOOD / WOOD_LT / PLASTER / STONE / KAWARA / SHOJI）
  → glTF 匯出：一材質一 primitive（實測 Primitives created: 6）
  → Godot 匯入：Mesh 6 surfaces，材質名帶著
  → gen_lib.semantic_mesh()：逐 surface 依**名字前綴**換成專案的 pbr() 材質
  → MultiMesh
```

`gen_town._emit_batches()` 的判斷依據是 **surface 數 > 1**，不是寫死模組名
—— Phase 2 加新模組時不用再改那裡。legacy 的四個單 surface 模組自動走舊路徑。

⚠ 名字比對要**長名優先**（`WOOD_LT` 不能被 `WOOD` 吃掉）。對不上的名字
保留 glb 自己的材質、不亂猜。

## 6. Known visual risks（人工審核時請特別看這幾點）

1. **屋身只有 2.29m。** 4.50 的總高扣掉 23° 屋頂（1.655）與棟（0.26）之後就
   剩這麼多。真壁造的立面節奏（腰→貫→內法→小壁）被壓得很扁，小壁只有
   0.32m。要更好的比例只有兩條路：放寬總高規格，或收屋頂坡度 —— 兩者都會
   動到使用者定案過的天際線，所以 Phase 1 沒動。
2. **丸瓦（本瓦葺き）是強烈的選擇。** 它比桟瓦貴氣、也更「寺社」。如果人間
   之里的一般町家應該是**桟瓦**（民家的常見形），這一輪要改的是屋面那 52 條
   半圓 —— 改起來很快，但要先定案。
3. **出格子只做在 bay0。** 四開間裡只有一格凸出去，正面因此不對稱。這是刻意
   的（町家的店・住・通り庭各佔各的開間），但如果要更整齊的商業立面，
   應該是 bay0+bay1 都出格子。
4. **貼圖比例還沒調。** 語意材質直接接上專案既有的貼圖組（plaster / planks /
   dark_wood / roof_kawara / stone_wall / shoji），uv1_scale 沿用材質庫的預設值
   —— 那組數字是配 blockout 的大面積調的，貼到 0.15m 寬的柱子上會太密或太疏。
   Phase 7（Materials/Polish）的事，但近景審圖看得到。
5. **169 棟裡有多少變成新版**：`machiya_f_a` 這個 kind 的每一棟都換了。
   其餘四種仍是 legacy blockout，所以街上現在是**新舊混排**。這是驗證
   「新模組進得了現有管線」的必要條件，不是最終狀態。

## 8. PHASE 1.1 —— 比例與屋頂語彙重平衡

**觸發**：Phase 1 的 technical pipeline 批准，Art Review 未批准。
指令範圍：只改 `machiya_f_a`，不進 Phase 2，不改 village layout，
不改其他四個 legacy machiya。

### 8.1 為什麼 4.50 救不回來

4.50 扣掉 23° 屋頂（1.655）與棟（0.26）之後屋身只剩 **2.29m**，
屋頂佔立面 **42%**。那不是造型問題是**預算問題** —— 屋身沒有高度可以長出
真壁造的節奏（腰→貫→内法→小壁），細節怎麼調都救不回來。

### 8.2 5.40 的分配

```
基礎 0.30 ┃ 屋身 3.36 ┃ 屋頂 1.50 ┃ 棟 0.24        總高實測 5.42
屋頂佔比 42% → 28%
```

多出來的 1.07m 屋身**不是拉高一層樓**，是長出 **厨子二階（つし二階）**：
江戸～明治町家的標準形，一階內法之上一條矮夾層，開**虫籠窓**。
不這樣做的話，3.36m 高的牆上半段會是一片空白漆喰 —— 屋頂不壓迫了，
換成牆壓迫。

坡度只收 2°（23° → 21°，約 3.8 寸勾配）。屋頂量體主要是被總高救回來的，
不是靠壓坡度 —— 規格明講「不要把町家變成低坡現代住宅」。

### 8.3 立面新增的兩件

| 構件 | 為什麼 |
|---|---|
| **虫籠窓（塗り込め）** | 它不是格子：木骨外面裹一層漆喰，所以櫺條又厚又圓、顏色跟牆一樣。剪影上是一排粗胖的白豎條，跟一階那排細而深色的連子格子形成對比 —— 這個對比就是町家立面的招牌 |
| **通し庇（橫貫整個面寬）** | 這是把「屋頂壓倒立面」真正解掉的那一件。3.36m 高的立面需要一條水平線切成「一階店面／厨子二階」兩段，否則屋頂縮小了牆還是一整片。原本只罩住入口的庇改成參數化元件，跑一次全寬 |

内法高從 1.72 放回 **1.85**（一般町家的常見值，5.40 的總高終於養得起它）。

### 8.4 本瓦葺き → 桟瓦葺き

使用者定案：一般 `machiya_f_a` 用樸素的桟瓦，本瓦葺（深半圓的丸瓦）留給
未來的富戶／寺社／地標。兩者在幾何上的差別就是實作上的差別：

```
本瓦：深半圓丸瓦壓在平瓦接縫上（凸 52mm）—— 剪影是一排粗肋
桟瓦：一體成型的波形瓦，只有淺桟（凸 22mm），而且**橫向的葺き足
      （每列的重疊段差）才是主節奏**
```

所以改成：**淺桟（定尺 305mm 間距）+ 橫向列線（葺き足）**。
⚠ 葺き足做成**貼在坡面上的細條**，不切開坡面本身 —— 切開的話坡面會變成
一階一階的樓梯，30mm 的段差在 5m 外根本看不出是瓦、只看得出是鋸齒。
軒先也跟著換：桟瓦的軒先瓦是**連續的唇**，不是本瓦那排圓形巴瓦。

## 9. PHASE 1.5 —— Human Village Vertical Slice

**目的**：停止雕單棟，用 9 棟建築的一段街回答「整體畫面能不能脫離
procedural demo」。**不是**整村重做 —— 169 棟、六座地標、河流、稗田邸
一律沒碰。

### 9.1 為什麼是獨立場景

新 map `maps/slice/`（`tools/gen_slice.gd`，46m 見方）。
village 的佈局是 `_block()` 的 169 筆 frontage 明表，改一格就要重跑全圖 +
五道閘門，一輪 6 分鐘；slice 一輪 **25 秒**。審圖要能**反覆**才有意義。

### 9.2 街道構圖：planned irregularity，不是 random scatter

**沒有一個 `randf()` 決定建築的位置、朝向或退縮。**全部寫在 `LOTS` 明表，
每一筆帶 `why` 欄位。亂數只出現在「同一種雜草的角度」這種層級。

| 手法 | 實作 |
|---|---|
| frontage setback | 退縮 3.0~3.9m，鄰棟之間差 0.4~0.7m（店面搶街是商業街的常態） |
| yaw variation | ±0.03 rad（約 1.7°）。大到看得出不是尺規排的，小到相鄰簷口不打架。真實町並みの不整齊就是這個量級 —— 歪的是**地界**不是房子 |
| alley gap | 北側 x=−3.7 一條 2.64m 的巷 |
| side passage | 南側 x=+1.2 一條 2.0m 的側巷（服務動線） |
| corner condition | `machiya_e_a` 轉 −90° 面向側街，主街只看得到它的山牆與側面 |
| roof height | 新版 5.42 / legacy f_b 4.50 / e_a 3.50 / b_a 9.40 |
| 兩側錯開 | 南北兩排的 x 刻意不對齊，街才不像走廊 |

⚠ **高的 legacy blockout（`machiya_b_a`，9.4m）第一版擺在南側門面，
結果整條街的第一眼全被它吃掉** —— 它是一個沒有細節的白盒子、又是全場最高，
旁邊是有軸組有瓦的新版町家，對比太殘忍。退到 z=+15.4 的**後排**之後，
它只在天際線上露出屋頂：「後面還有更深的街區」這個資訊拿到了，白盒子看不到。

### 9.3 地面：夯土為主，石板只在人真的踩的地方

規格：「目前大片亮色石板路太搶戲」。所以這裡**反過來**做：

- **主街整條是夯土**（mask 的 A 通道）。石板（R）只出現在**店門口** 2.4m
  見方那幾塊、以及**井邊**（打水一定是硬鋪面）。village 是「有店就有石板」
  鋪成一整片，這裡是「店**門口**才有」。
- **路是壓實下陷的**：比兩側低 7.5cm（幾百年走出來的）。
- **車轍**：兩條沿街的淺溝，離路心 ±1.15m（板車輪距），深度只給 **25mm**
  —— 再深就變排水溝而不是輪痕，而且玩家走過去膠囊會頓一下。
- **建物腳下微微墊高** 5.5cm：土堆在牆邊，不是切齊。
- **牆腳的夯土帶**：第一版只鋪到牆外 1.5m，實測房子腳下還看得到亮綠草地
  —— 房子讀成「放在草皮上的模型」，正是規格要解的那件事。加寬到 3.4m、
  貼牆那圈給滿。
- 石溝 152 節 + 路邊石 152 + 踏石 24（**只在跨溝與門口**，不鋪成路）
  + 牆腳碎石 234。
- 草**只長在沒踩實的地方**（`mask_at` 的 A/R 通道當條件），所以街心沒草、
  巷底與牆角有。

### 9.4 道具：只用既有資產 + 手工小件，不開新 glb 不開新材質

既有 glb（7 種 46 件）：`prop_crate` / `prop_basket` / `prop_barrel` /
`prop_noren_a,b` / `prop_kanban` / `prop_chochin`。
掛的（16 件）用模組 manifest 的 `facade` 錨點對齊**真的門與樑**。

手工小件（`lib.box/cyl` + 既有材質，**沒有新 glb、沒有新材質**）：
水桶（含桶箍與提手）・掃帚（**靠著牆**站 —— 立在空地上會像插在地裡的棍子）・
柴堆（三層錯開）・盆栽・晾衣（兩竿三布，掛在**後院**不是店面 ——
商業立面上晾衣服是住宅語彙，位置錯了就穿幫）。

### 9.7 仍然存在的 Demo 感來源（誠實清單）

1. **貼圖比例是現在最吵的東西。** 漆喰在街景裡讀成**斜向的瓦楞板**
   —— `uv1_scale` 是配 blockout 的大面積調的，貼到 0.15m 的柱與 1.6m 的
   嵌板上完全不對。這一項現在比幾何還傷畫面。
2. **夯土讀成粗砂礫。** `terrain_path` 貼圖有大顆白石粒，鋪成街之後是
   「碎石場」不是「踏み固めた土」。要一張真的夯土貼圖（或把現有的縮小 + 壓對比）。
3. **legacy 道具的解析度跟新建築對不上。** 提灯是黃色圓塊、木箱是素面方盒
   —— 它們是配 blockout 做的，現在站在有軸組有瓦的町家旁邊。
4. **只有一種新町家。** 六棟 `machiya_f_a` 是同一份 mesh，面寬、開間、
   建具全一樣。街上重複感的主因 —— 這是 Phase 2（Architecture Kit）的事，
   本輪明令不做。
5. **後排的白盒子**仍在天際線上（退到後排只是讓它不搶戲，不是解決）。
6. **沒有 NPC 動作、沒有煙、沒有晾衣飄動** —— 靜態畫面的「有人生活」目前
   全靠道具擺位，動態層還沒有。

## 10. PHASE 1.6 —— Legacy quarantine

**觸發**：slice 的空間構圖批准，但 Art Review 被 legacy white-box 干擾。
指令：把明顯低品質／白盒／屋頂未完成的 legacy 建築移出主要視野，
**不刪資產、不改 village、不重做 169 棟、不進 Phase 2**。

### 10.1 三棟被移出的 legacy 與判準

| 建築 | 原位置 | 判準命中 | 處置 |
|---|---|---|---|
| `machiya_f_b` | 北側門面 x=+2.4 | 白色未材質化・silhouette 未完成 | 換成 `machiya_f_a` |
| `machiya_b_a` | 後排 z=+15.4 | **高度搶戲但細節不足**（9.4m 白量體，退到後排仍在天際線上讀成一塊白） | 換成兩棟妻入り的 `machiya_f_a` |
| `machiya_e_a` | 轉角 x=+21.6 | 白色未材質化 | 換成妻入り的 `machiya_f_a` |

**slice 內現在 legacy 建築 = 0。**⚠ 資產一個都沒刪，village 的 169 棟照樣
在用它們 —— 這裡只是**不放**。

### 10.2 一種模組怎麼撐 10 棟

平入り／妻入り都是町家的正統形。同一份 mesh 轉 90° 之後，街上看到的是
**山牆＋破風板＋懸魚**而不是格子立面 —— 剪影完全不同。所以：

- 前排 7 棟 **平入り**（屋脊平行街道，格子立面朝街）
- 轉角 1 棟 **妻入り**（山牆朝側街）
- 後排 2 棟 **妻入り**（屋脊垂直街道，從街上看是兩片山牆疊在前排屋頂後面）

這不是偷懶，是免費的變化。但它**不能取代** Phase 2 —— 見下。

### 10.3 隔離的代價（誠實回報）

1. **天際線變平了。** 全場同一份 mesh、同一個總高 5.42。原本 legacy 的
   9.4m 是唯一的高點，移出之後屋脊全部齊高。妻入り換得的是**剪影方向**的
   變化，換不到**高度**的變化。這是 Phase 2（Architecture Kit，8~12 種
   真正不同的 silhouette）最強的存在理由。
2. **面寬也全一樣**（7.6m）。町並みの節奏靠的是間口の寬窄交替，現在沒有。
3. 前排七棟的立面**逐格相同**：出格子永遠在左、大戶口永遠在右起第二間。
   走過去會看到同一張臉七次。
