## 楓樹冠 v2（2026-08-05）

使用者看完 v1 blockout：「球體樹我覺得不太有我想要的」。

**病根**：v1 的樹冠是分層的橢球（icosphere subdiv 2 + 縮放），跟 v15 生垣
一模一樣的問題 —— 光滑封閉曲面不管怎麼上色都是球。

**改法**：搬 `make_hedge.py` 已驗證的「凹凸殼 + 上千片小葉打碎輪廓」，
換成球面參數（`_canopy_surf`：標準球面座標疊 4 個隨機頻率正弦擾動）。
全場只有 2 棵巨樹（不像生垣要撒滿全村），面數放心加密——單棵 5 叢
樹冠、每叢 65~110 片葉，`hieda_blockout.glb` 從 3,192 面漲到 **11,656 面**，
但整棵樹加兩棵仍是**一份 mesh、一次 draw call**，不影響效能預算。

**這不是往寫實走**——葉片仍是 flat shading 的扁平三角片、頂點色、
無貼圖，符合規格 §1.1「偏卡通」。差別只在輪廓：光滑橢球 → 碎邊的雲朵狀。

新增 `_auto_quad()` 用面法線對球心方向自動判斷繞序，不用像
`make_hedge.py` 那樣手動推 `flip=(sd<0)`（凹凸球面手推很容易推錯）。


## 唐破風玄関（2026-08-05）

清單上技術含量最高的一件，做完了。

**S 曲線怎麼來的**：破風輪廓是中央上凸（起り）→ 兩翼下凹（反り）→ 末端上勾
（簷角），三段曲率、兩個反曲點。硬湊控制點會湊很久，但 `sin²(sπ/2)` 天生
就是這條 S —— s=0 附近二階導為正、s=1 附近為負，反曲點正好在 s=0.5。拿它
當「從棟往下掉多少」，一個 `drop` 參數就控制整條曲線深度。末端那一勾另外
加 `s⁶`，六次方在 s<0.75 幾乎是 0，只有最外側十幾 % 抬得動，剛好是簷角
位置，不會把中段的凸壓平。

**屋面不是把曲線平移拉出去**（那是圓筒，看起來像水管）：從牆面掃到簷口的
過程半寬 3.35→3.85 外張、棟高 4.45→3.75 下傾，每一圈都是一條不同的 S 曲線
—— 這就是「曲面斷面 + 寬度方向切妻疊合」。

**高度被上下夾死**：上面 y=-8.98 有裳階簷口壓著（底 4.54），下面有腰簷
（頂 3.36）。4.45→3.75 是量出來剛好穿過中間的，改之前要重算這兩個夾擠點。

**順手修掉的兩個既有缺陷**：

1. *階梯以前走不上去* —— 舊版頂階在 y≈-8.6，而縁側從 -9.33 才開始，爬到
   第三階就撞地板，前面還橫著一整排不斷開的高欄。現在階梯落在縁側外緣
   往外，高欄與腰簷都在玄関處開口（`GATE_HW` 統一控制）。
2. *縁側懸空 0.95m* —— 基壇原本只到 ±(d/2+1.1)，縁側外緣卻在 ±(d/2+2.05)。
   以前被高欄擋著看不出來，高欄一開口就露餡。基壇進深改到 d+4.1。

**踩到的坑（值得記）**：階梯本來是 5 個實心 box 疊的，box 巢狀所以側面全部
落在同一平面互相重疊。共面的兩張面會讓算圖器的陰影線一離開表面就打到對方
——整片階梯側面算成**純黑 (0,0,0)**，關掉太陽只留環境光還是黑的。看起來
像破洞，`ray_cast` 打下去卻是好好的面、法線對、顏色對，錯的是「有兩張」。
改成分段鋪面的開放殼（蹴込＋踏面＋兩側，不畫底面與背面）就乾淨了，順便
從 30 個 quad 降到 20 個。

面數：`hieda_main` 2,000 → **2,532**。多的幾乎全在 S 曲線的橫向細分
（nt=18）與破風板，砍掉就只剩一塊雨遮。能省的先省了：屋面深度方向是
直紋曲面（`hw_at`/`pk_at` 都是 u 的一次式）所以 nd 只給 2、階梯開放殼、
被妻壁完全擋住的蟇股整組拿掉。仍然是一份 mesh、一次 draw call。


## 前庭裝飾輪（2026-08-05）

使用者拿參考圖（求聞編年史・稗田邸門前）給了一份四點規格，範圍鎖定
「門與前庭」，**主屋外觀凍結**。`hieda_main.glb` 這輪逐位元組沒變動。

1. **格子塀**：原 §3 規格是平的白壁土塀。改成分層 —— 腰石垣 → 白漆喰 →
   **上段一條深色木格子帶** → 冠木 → 兩坡瓦頂。理由是尺度感：一面 3.5m
   高、38m 長的純白牆在遠景就是一條白帶子，橫向的格子把它切成有節奏的
   段落，遠看深淺相間、近看才是木格柵。
2. **對稱添景**：狛犬 / 石燈籠 / 松各一對，由內而外、由窄而寬排成八字
   （x = ±4.7 / ±6.8 / ±9.2），站在門口往內看會把視線收束到唐破風玄関。
   狛犬擺在「從外側往內約 1/3」處（前庭深 22.6m → y≈-26.5）。
3. **參道**：原本的「邊緣與草地不規則交錯侵蝕」整個拿掉，改成邊界筆直、
   固定目地的切石鋪面，從外參道一路連到唐破風石階腳下不斷開。侵蝕感
   讓路看起來像沒人維護的野徑，跟「貴族宅邸的正式參道」是反的。
4. 石燈籠是這輪新做的資產（`make_props.py` → `stone_lantern.glb`，春日
   燈籠形）。火袋不做實體六角柱 —— 上下兩片盤 + 六根角柱鏤空，剪影才
   讀得出是「透光的燈室」而不是一顆石頭疙瘩。

**資產不抄第二份**：狛犬／石燈籠／松都是用 `place_asset()` 把定案的
`.glb` 載進來擺位，造型永遠是 `make_props.py` 說了算。抄一份幾何過來
就等於開第二個真相來源，下次改狛犬一定有一隻沒跟到。
匯入時要強制把顏色屬性正規化成 `BYTE_COLOR / CORNER / "Col"` ——
`export_sel()` 的 join 是照名字合併屬性的，名字對不上（glTF 匯入器有時
給 "Color"）合併後那半邊會整片變白。

`hieda_blockout.glb` 12,180 → 19,514 面（牆 + 門 + 六件添景），仍是
一份 mesh、一次 draw call。


## 前庭修訂輪 2（2026-08-05）

使用者驗收上一輪後指出三點，範圍仍鎖前庭、主屋不動（`hieda_main.glb`
再次逐位元組不變）。

1. **狛犬被門吃掉** —— 放大 18%（2.75 → 3.25m），同時把門柱從 3.60 降到
   3.30。兩邊各讓一步比只動一邊自然：現在狛犬跟門柱幾乎同高，在門前的
   構圖裡是同一個量級，不再是門洞旁的小擺設。
   狛犬本身**維持嚴格左右對稱** —— 牠是儀式性的門衛，擺歪只會像沒對齊。

2. **松與燈籠太機械** —— 上一版兩側完全鏡射、而且間距均等。改法是把
   四個物件的座標／旋轉／縮放**拆成明表寫死，放棄 for 迴圈鏡射**：
   迴圈天生只生對稱，要不對稱就得先放棄迴圈。
   　右側：燈籠緊挨狛犬（1.9m）、松再拉遠（4.8m）—— 疏密對比大
   　左側：燈籠退遠（3.6m）、松貼著燈籠（2.9m）—— 節奏跟右側相反

3. **牆腳跟地面像兩個物件對接** —— 三件事一起做：
   - **石垣勾配**：牆腳從等寬 box 改成上窄下寬的梯形（半寬 0.525→0.79）。
     等寬 box 跟地面交出一條完全垂直的硬邊，那就是「一塊牆放在一塊地上」。
   - **犬走り**：牆腳外一圈兩階碎石帶。
   - **接觸陰影**：貼牆那條窄帶必須比**草地還暗**。量過渲染值 —— 草地
     albedo 0.22 出來是 130，第一版暗帶給 0.285 出來是 144，比草還亮，
     整條讀成一道混凝土路緣，等於又多加一條硬邊，跟要解的問題正好相反。
     壓到 0.15 之後才真的讀成牆腳的陰影。

**順手修掉兩個上一輪的洞**（都是這輪加東西才炸出來的）：
- 門柱整根埋在牆身裡 —— 牆的缺口只讓了門洞（3.6），沒讓門柱（±3.95，
  寬 0.70），柱子完全包在 0.86 厚的牆身內，整座門只剩一片浮在開口上的
  屋頂。缺口改成 `MON_HW + 2*MON_POST_HW`，柱身也加厚到 1.10 露出牆面。
- 門柱的犬走り跟牆的犬走り**共面重疊** → 兩張同法線的面互相擋掉環境光，
  地上出現兩塊全黑補丁（唐破風那輪階梯側面的同一個病，第三次踩到）。
  兩者的 `hb` 取同一組 0.79、x 範圍精確接齊，改成相鄰而不重疊。
- 場景層原本又宣告一次 `GATE_HW = 3.6`，把模組層的 `GATE_HW = 2.9`
  （唐破風玄関開口，`build_house` 在用）整個蓋掉。改名 `MON_HW`。


## 後院（2026-08-05）

使用者給了完整規格，範圍鎖後院；門庭與主屋都不動（兩者這輪都逐位元組不變，
`place_asset` 雖然改過但純量縮放的行為完全相同，門庭 render 對照過一致）。

**設計語言刻意跟前庭相反**：門前是儀式性的左右對稱，後院沒有任何一對鏡射
物件、沒有等距排列。但「不對稱」不等於「亂撒」—— 每件都有構圖理由：

| 元素 | 擺這裡的理由 |
|---|---|
| 水池貼主屋北面 | 南岸那片鏡面才照得到屋頂與楓樹 |
| 涸れ滝在池北緣 | 從主屋往北看，視線越過鏡面正好落在瀑布上 |
| 枯山水獨立在東側 | 主角要有自己的空間，不跟日常物件擠 |
| 菜園退到西北角 | 最私密、最不需要被看見的擺最裡面 |

### 水池
- **深度漸層**：池底真的做出深淺（中心 -1.25m），水色由實際深度算出來。
- **鏡面**：朝主屋那側（-y）留一片無石水面，往天空色偏。
  ⚠ 鏡面色本身也要**隨深度變暗**：第一版整個 -y 楔形不分深淺塗同一個淺色，
  等於在最深的地方畫出最淺的水，鏡面把深度漸層直接抵銷掉。淺處映天、
  深處映屋頂量體，兩件事才同時成立。
- **涸れ滝**的落點用**實際池緣半徑**算，不寫死座標 —— 池岸是隨機起伏的，
  寫死的話換個 seed 石階就整組站進水裡（第一版正是如此）。

### 枯山水（後院主角）
- **砂紋是同心圓、圓心在懸浮石正下方** —— 耙紋不是裝飾，是在敘事：
  像石頭落水那樣盪開，把「靈氣正在擾動沙面」畫出來。所以不用平行直紋。
- **石組主賓**：主石立起（2.35m）、最大、偏離中心；添石矮、退後、`yaw`
  直接算成朝主石傾。三顆一樣大平均擺開就只是「三顆石頭」，沒有主從就
  不是石組。
- **主石基部一圈苔**：只在腳下、不爬石身。這圈苔在講年份 —— 石頭立得夠久
  才長得出來，稗田家一千年的家業要有一個地方看得出時間。
- **懸浮石**：兩塊、高度不齊（1.14 / 0.86m），中間裂開一道縫，縫內暖白。
  裂縫內壁切成長短不一的「筆畫」（亮/次亮交替），遠看是一條光帶、近看
  有字跡感 —— 呼應阿求記錄幻想鄉緣起的設定。

⚠ **發光是 Godot 端的 emissive 材質**，`.glb` 只帶頂點色。兩階光色的紅通道
都推到 0.92 以上，而全場其他顏色最高只到 `C_SHOJI` 的 0.87 —— 所以
「R > 0.92」是一條乾淨的判別線，Godot 端可以直接拿它挑出要發光的面。
（預覽圖裡的光是 `pv_garden.py` 用同一條線接的 emission，只是預覽。）

### 這輪踩到的坑
- **砂紋變成一圈圈死黑的環**：每圈各自抽噪聲，內圈在某些角度胖過外圈 →
  兩圈交叉重疊 → 共面同法線互相擋光。改成所有圈**共用同一組噪聲相位**，
  半徑只差倍率，`r_i(θ)=r_i·k(θ)` 對 i 嚴格遞增，數學上保證不交叉。
  兩顆懸浮石的受光池也同樣重疊（半徑和大於間距），各給各的高度錯開。
  → 階梯側面 → 犬走り → 這裡，**同一個病第四次**。教訓寫死在這裡：
  **任何時候要在同一個高度鋪兩片面，先證明它們不會重疊。**
- `_organic()` 的三個正弦各自最大 `amp`，疊起來最壞到 ±3·amp，所以
  `amp=0.15` 實際讓半徑在 0.55~1.45 倍間跳，池岸長出尖葉瓣（星形）、
  半徑上限也抓不準。改成把三個振幅正規化成總和 = `amp`。
- 挟石寫成 `z_top + hh`，兩塊變成 4.7m / 4.1m 的巨柱，讀起來是兩根清水模
  柱子夾一道樓梯。`hh` 應該是總高。
- 受光池第一版鋪到 `fs*1.7` 又混得很重，兩片大白盤正好蓋掉砂紋圓心 ——
  而圓心就是整個敘事的重點，等於為了加光暈把主題擦掉。

`hieda_blockout.glb` 19,514 → 25,492 面，仍是一份 mesh、一次 draw call。


## 後院 修訂輪 2~4（2026-08-05）

### 輪 2：尺度修正
第一版水池 r=6.4（直徑 13m）、枯山水 r=7.0，對上 25.5m 寬的主屋只有一半
不到，讀起來是「屋子旁邊兩個小擺設」而不是庭園本身。
- 水池 → r=16（2.5×，直徑 32m ≈ 主屋寬）
- 枯山水 → r=14（2×），砂紋圈數 16 → 28（半徑翻倍還用 16 圈的話間距
  0.87m，粗到讀不出耙紋）
- 拉開間距：主屋背面 → 水池南緣約 17m、→ 枯山水南緣約 18m（原本只有
  1~4m）；水池東緣 ↔ 枯山水西緣約 8m（原本幾乎相連）。每一區各自要是
  一個「目的地」。
- 涸れ滝落差 2.55 → 4.6m，石階尺寸跟著 `z_top` 等比縮放（大池配小瀑布會
  失衡），但仍遠低於池本身的尺度 —— 它是池裡的重音，不是蓋過池的主角。
- 石組與懸浮石一併放大約 1.6×：砂床變兩倍而石頭不變的話，主賓關係在
  遠景就消失了。懸浮高度仍守在 0.8~1.2m。

### 輪 3：水面
使用者：水面是一圈圈硬邊色環，像地形圖不像水。

**病根在 builder，不在配色**：`B` 一直是「一張面一個顏色」，所以漸層只能
靠「一圈一個色」堆出來 —— 六圈就是六條等高線。加了 `tri_v`/`quad_v`
（每個角各自一色，面內線性內插），再把水色寫成一個**連續的位置函式**
`wcol(x,y)`，色帶邊界就消失了。

`wcol` 疊四件事：深度漸層 → 鏡面（色本身隨深度變暗）→ 天光柔斑（假的
specular，真正的粗糙度是 Godot 材質的事）→ 岸際往岸石色收（水與石之間
不是一刀切）。柔斑第一版給 0.42、半徑 0.46r，整池被洗成一片淡灰藍，
深度漸層讀不出來 —— 收到 0.26 / 0.34r。

## 後院 界線改生垣 + 灌木叢重做（2026-08-05）

### 竹垣 → 生垣（刈込み）
竹垣讀不出「這是庭園的邊」—— 太細、融進場景裡。改成刈込み生垣。

**能不能直接複製村內的生垣？技法可以，資產不行。**
`make_hedge.py` 的模組 `hedge_a` 是 **5,786 面／2.4m**，這圈約 240m 要
~100 個模組 ≈ **58 萬面**，而整個 blockout 現在才 4.2 萬。村內撐得住是因為
`gen_village.gd` 走 **MultiMesh**（每種變體一次 draw call）；blockout 只有
一份 mesh，沒有這個選項。所以照**技法**重寫、密度按 blockout 調。
Godot 端接手時應該換回 MultiMesh + `hedge_*.glb`。

那支驗證過的三件事全部照抄：
1. **殼要很暗**（`HULL_DARK` 0.020）—— 殼是樹籬內部，本來照不到光。
2. **殼與葉共用同一組剖面**，否則葉撒不到側面，露出光滑的殼。
3. **葉片短而寬**，不是細長三角形（細長的會變成仙人掌）。

規格對應：斷面側面近垂直（0~0.62 高度幾乎不收）、頂緣才收 → 刈込み的讀法；
高度沿線 1.0~1.4m 起伏；三處壓低 + 兩處斷開留視線缺口（一圈等高的綠牆會把
後院關成盒子）；木戶處維持 5.5m 開口。用色深且帶藍灰，與灌木叢的亮綠分開。

### 灌木叢：「像西瓜」的真正原因（第四版才找對）
前三版一直在調**形狀**（加大起伏、改多團塊），方向是錯的。對照
`make_hedge.py` 的結論才看出三個都沒照做：

| | make_hedge.py | 我的前三版 |
|---|---|---|
| 殼亮度 | 0.020 | **0.115（亮五倍）** |
| 葉片寬長比 | 0.38~0.62 | **0.36（細長刺）** |
| 葉叢密度 | 430 叢／7.8m² | **44 叢／55m²** |

殼一亮就變成主視覺、葉子只像插在上面的刺 —— 這才是西瓜感的來源。

**第四塊拼圖是尺寸本身**：原本一叢 rx=2.3（將近 5m 寬）根本不是灌木，是樹
的體積。球面積隨半徑平方漲，5m 的球約 55m²，要蓋滿得撒上萬片葉（那支撐得
住是因為一個模組只有 7.8m²）。面數上不可能，於是殼永遠露著。
收到 rx≈1.25（約 23m²）同樣葉數才蓋得住；體積用**叢生**（一處 2~3 株）
補回來，順帶比單顆巨球自然。

## 樹：從「棍子上插球」改成遞迴分枝（2026-08-05）

使用者：樹不像樹，像一顆球插在棍子上。這是**結構問題**，不是表面問題 ——
舊 `build_maple` 就是「八角柱樹幹 + 2~3 顆 add_canopy 球」，樹冠中心寫死在
樹幹頂端上方的偏移量，跟枝條完全無關。再怎麼調球的凹凸都救不回來。

改成遞迴分枝：樹幹長一段 → 分岔 → 子枝再長再分（深度 4），半徑逐段收細、
每次分岔再乘一個 <1 的比例。**樹冠 = 所有枝端周圍葉子的聯集** —— 枝伸到哪
冠就到哪，枝不對稱冠就自然不對稱。

### 迭代（八版，每版的病都不一樣）
| 版 | 症狀 | 病根 |
|---|---|---|
| v1 | 深色板蓋在枝上 | 葉團半徑 1.65m（3.3m 的球），15 叢葉根本蓋不住 |
| v2 | 平底蘑菇帽 | 沒有 leader —— 主幹在第一次分岔就消失，所有枝從同一高度散開 |
| v3 | 一頂頂尖帽子 | 葉團殼只細分 2×5，極點收成尖錐 |
| v4 | 海膽 | 每個枝端一顆殼 + 放射狀葉；殼表面 3m² 要蓋滿得數百片葉，撒不起 |
| v5 | 樹上掛鳥巢 | 擋光用的暗色團塊在葉間露成深色多面體 |
| v6 | 枝條光禿 | 葉只堆在枝末端一點，枝的外段整段裸露 |
| v7 | 冠太透、分三坨 | 球內均勻取樣 → 一半葉子埋在內部，對剪影零貢獻 |
| v8 | ✅ | 半徑改 u^0.45 偏外側取樣；首層分 4 枝讓限interleave |

**關鍵三招**（都是既有教訓的再應用）：
1. 葉子撒進枝端周圍的**體積**，不做「每枝端一顆殼」—— 密度算不過來。
2. 擋光用**顏色**不用幾何：靠近枝端的葉往暗色混，外緣保持鮮亮。
   任何硬幾何塞在葉間都會露成異物。
3. 半徑取 u^0.45 偏外側 —— 均勻取樣有一半葉子被自己擋住，白花面數。

前庭拱門巨樹的**骨架保留**（枝真的橫伸 5m 形成拱），只把 5 顆 add_canopy
球換成沿枝端撒葉。
