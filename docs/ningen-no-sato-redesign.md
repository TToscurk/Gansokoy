# 人間之里 街區重設計 Feature List

**來源**：使用者 2026-08-05 的開工規格（含空拍幻想鄉參考影片修正）。
**狀態標記**：✅ 已做｜🔨 本輪動工｜⏳ 排隊中｜🚫 明確排除

## 範圍
本階段只做**街道／街區重設計（地圖幾何）**。明確排除：
- 🚫 戰鬥／衝刺用的碰撞牆準備（明確延後）
- 🚫 農田系統（獨立階段，未開工）
- 🚫 人群／NPC 模擬（等 NPC 系統存在）

## 1. 複合街區（Compound Block）
| 項目 | 規格 | 狀態 |
|---|---|---|
| 打破格線 | 每街區 3~4 棟町家，交錯排成 **L 形或ㄇ形** | 🔨 |
| 前後錯位 | 棟與棟之間前後錯 **1~2m**，拆掉僵硬的矩形院牆 | 🔨 |

## 2. 階梯天際線（修訂版 —— 更戲劇化）
| 項目 | 規格 | 狀態 |
|---|---|---|
| 前排 | **4.5~5.5m** | 🔨 |
| 後排 | **9~10m**（接近翻倍，不是原本溫和的 2.5m 差） | 🔨 |
| 村緣 | 極端縮小至 **3.5m** | 🔨 |
| 後排屋頂 | **45° 斜度**，給街道視角壓迫感 | 🔨 |
| 驗證方式 | **必須在引擎內街道視角驗證**，不能只看俯瞰 blockout | 🔨 |

## 3. 12m 主橋
| 項目 | 規格 | 狀態 |
|---|---|---|
| 形制 | 日式**半拱木橋**，寬度對齊 12m 主路 | 🔨 |
| 拱高 | 頂點 **+1.5m** | 🔨 |
| 欄杆 | **1.1~1.2m** | 🔨 |
| 親柱 | 隨橋寬等比放大，站在橋上要讀得出份量 | 🔨 |
| 鏤空欄杆 | 上下橫木之間留空，配合**確認過的日照方位**投影 | 🔨 |
| 過橋不對稱 | 過橋後**左高壓／右低開**，刻意不對稱 | 🔨 |

## 4. 水系優先的規劃邏輯（重大修正）
看過空拍幻想鄉參考影片後確立：**水路是城鎮的結構脊椎，不是撒在格線上的裝飾**。
| 項目 | 規格 | 狀態 |
|---|---|---|
| 先定河道 | 先畫蜿蜒河道，複合街區**順著水的曲線**排，不是先畫格線 | 🔨 |
| 小橋 | 路網自然需要過水的地方補 **1~2 座小橋** | ⏳ |

## 5. 街道生活密度層（**後續疊加，本輪不做**）
| 項目 | 規格 | 狀態 |
|---|---|---|
| 地面雜物 | 商品溢到街上、疊起的籃／桶 | ⏳ |
| 簷下吊掛點 | 布旗、燈籠、招牌 —— 密度依商業／住宅氛圍變化 | ⏳ |
| 地標建物 | 每個大街區一座（水車、鐘樓），打破町家的均質 | ⏳ |
| 背景層次 | 遠景屋頂剪影 + 山，給出街區以外的尺度感 | ⏳ |
| 花樹密度 | 同種花樹**大群聚**做色塊衝擊，不是散點單株（稗田邸教訓） | ⏳ |

## 6. 建置策略（已定案）
| 決策 | 內容 |
|---|---|
| **參數化產生器優先** | 先寫町家街區產生器（參數：街區尺寸、高度梯度、對水角度），再談手擺 |
| **第一步就 MultiMesh** | 不重蹈稗田邸「單一 mesh blockout、事後轉換」的錯 |
| **Blender 只做模組** | 町家變體、橋、吊掛道具各自輸出獨立 `.glb`，**不在 Blender 組整條街** |
| **佈局邏輯在 Godot** | 資料驅動的產生器腳本（讀模組庫 + 參數，MultiMesh 批次實例），沿用 `gen_village.gd`／`gen_kourindou.gd` 模式 |
| **絕不先合併建築群再匯入** | 合併就毀掉 MultiMesh 的意義 |
| 多代理平行 | 更大規模時考慮（等共用模組庫驗證過） |

## 本輪交付順序（使用者指定）
1. Blender/Godot 分工先確立（模組 vs 佈局）
2. **町家街區參數化產生器** —— 真正的第一交付物，不是渲染圖
3. **河道路徑** —— 定義／確認蜿蜒河道穿過城區的走法（佈局跟水走，先有水才能擺街區）
4. 1~3 就位後：用產生器生出第一個複合街區（**寬橋核心區**），出預覽給使用者驗收
   —— 跟稗田邸一樣的節奏：先做一件、驗收、再批量。

## 第一輪實作：寬橋核心區（2026-08-05）

### 交付物
1. **模組庫** `assets/blender/make_town.py` → 6 個 .glb + `data/town_modules.json`
   | 模組 | 實測（從匯出的 glb 量，不是設定值） | 面數 |
   |---|---|---|
   | machiya_f_a / f_b | 總高 4.80 / 5.40（規格 4.5~5.5）✓ | 354 / 464 |
   | machiya_b_a / b_b | 總高 9.40 / 9.90（規格 9~10）、屋面 **45.0°** ✓ | 614 / 654 |
   | machiya_e_a | 總高 3.50（規格 3.5）✓ | 314 |
   | bridge_main | 寬 **12.0**、拱 **+1.50**、欄杆 **1.15**、親柱 0.50 見方 ✓ | 1,168 |
   高度**由目標總高反推屋身高**（規格由建構保證）；45° 不准用 y 縮放做（縮放會改斜度）。
2. **參數化產生器** `tools/gen_town.gd`：臨街線/進深方向/排配置(rows)/錯位範圍(jog)/
   包角(L/ㄇ)/對水角度(river_end) 全參數化。第一步就 MultiMesh（5 種模組 5 draw call）。
3. **河道提案** `RIVER_SPINE`（全鎮，村座標）：北端 x≈108 出圖（保留湖連接鉤子）、
   蜿蜒穿過鎮東側、主橋 (66,30)、南端 x≈64 出圖。
4. **試驗場景** `maps/townlab/`（獨立，不碰 village.tscn）+ 引擎內 xvfb 街道視角截圖
   （規格要求的 in-engine 驗證）。

### 佈局驗證（從擺位表量，不讀產生器的 audit）
- 同排鄰棟前後錯位：西北前/後排、西南前排、東北臨街、東南 —— **全部落在 1.0~1.8m**（規格 1~2m）✓
- 河畔棟 yaw 對河道切線偏差 **0.0°** ✓（街區跟著水彎）
- 過橋不對稱：東北臨街=後排模組(9.4/9.9m、退 0.4m)、東南=村緣/前排(3.5/4.8m、退 2.2m+)✓

### 街道視角的誠實發現（待使用者裁決）
**正對面平視時，後排 9~10m 只勉強探出前排屋脊**：眼高 1.7、前排脊 4.8@10m
（視線斜率 0.31）、後排脊 9.4@24m（需 0.32）—— 幾何上剛好卡在臨界。
斜視角／橋上／街尾的階梯感都清楚（t2 尤其強）。若要正對面也讀出階梯，
選項：(a) 後排整排推到 10m 上限、(b) 排間距縮小、(c) 前排壓到 4.5。

### 兩個舊決策的處置（記錄在 gen_village.gd 註解裡）
- 「水道直直的就好不要轉彎」→ 使用者看空拍參考後**明確推翻**，改蜿蜒脊椎。
- 「主街 8m、11m 像機場跑道」→ 那是對南北本通說的。**12m 軸放在過河的東西向
  主路**（有 9~10m 町家壓著、12m 橋收束），本通維持 8m 不動。

### 整合時要使用者決的
- 河道最貼近 鵜呑亭 街區（東緣 x=47）時岸線距 ~8m；核心區西側街區與現有
  鵜呑亭/火見櫓 footprint 重疊 —— 批量時這兩個地標**搬遷或整合進臨河街區**
  （臨河食堂在題材上其實加分）。
- 舊東緣河 + 直水道與新河道的整併。
- 橋朝向已跟 daynight 太陽配過：影子永遠往 -z ±40°，東西向橋面的南欄整天
  在橋面上投欄影（引擎內 15:42 截圖確認）。

### 踩到的坑
- `--map=` 等旗標是 `get_cmdline_user_args()` —— 要放在 `--` 之後，不然靜靜載預設圖。
- glTF 匯回 Blender 會轉回 Z-up + 法線整組反向：量測腳本高度取 `.z`、斜度取 `|n.z|`。
- 橋面板頂點只在 y=±6 角落：取樣帶取錯就量出 0.00 的拱高（量測腳本也要驗證）。
- 立面元素放成 +y（牆內側）→ 全部埋牆 + 二階窗背面與牆共面（黑洞，第五次）。
- 欄杆橫木用水平箱逐段近似拱 → 鋸齒樓梯；改沿拱斜切的連續稜柱。
- lib.terrain / river_water **自己掛節點進 root**，再 add 一次會炸 already has a parent。
