# 《東方幻想鄉》獸道完整開發規格書 V1.0

**狀態：** 規劃完成・待開發  
**開發環境：** Claude Code + Blender MCP + Godot 4  
**關卡類型：** 第三人稱探索、劍術戰鬥、BOSS 戰  
**美術方向：**《對馬戰鬼》自然環境 +《隻狼》關卡設計 +《原神》幻想氛圍

這份規格是針對目前的幻想鄉專案設計，包含：

- **4 個主要場景**
- **66 類資產**
- **29 項開發任務**
- 檔案結構、製作標準、碰撞配置、效能要求與最終驗收清單

## 一、世界定位與關卡配置

獸道是一條穿越普通日式森林的泥土道路，連接人間之里與博麗神社方向，並可依遊戲設計加入通往迷途竹林的支線。

**最重要的原則：獸道先是一條真正能走的路，其次才是一個戰鬥關卡。**

### 關卡連接示意圖

```text
                  人間之里 V2（既有場景）
                           │
                           ▼
                    S01 · 獸道入口
            寬闊土路、農村外緣、稀疏林地
                           │
                           ▼
                    S02 · 森林深處
            茂密林道、倒木、小溪、妖怪痕跡
                           │
                           ▼
                    S03 · 森林岔路
             主線往博麗神社，支線往竹林方向
                      ╱          ╲
                     ▼            ▼
             S04 · BOSS 空地   迷途竹林方向
               主線戰鬥區      預留支線出口
                     │
                     ▼
                博麗神社方向
```

> 這是遊戲關卡設計，不代表原作已有這條明確的三地連通路線。初版只做獸道，不製作完整的博麗神社或迷途竹林。

## 三、四個場景的資產配置

有了資產表，Claude 還需要知道哪些東西應該放在哪裡。

| 場景 | 主要使用資產 | 密度與配置 | 玩家體驗 |
|---|---|---|---|
| S01 入口 | G01～G08、V01～V10、H01、H03 | 樹木稀疏，人為痕跡較多，道路清楚 | 安全、自然 |
| S02 深林 | G01～G10、V01～V11、N01～N10、Y01～Y07 | 樹木密集但保留林隙，岩石與倒木自然分群 | 探索、警覺 |
| S03 岔路 | G01～G09、V01～V12、H01、H04、H06、H09 | 道路交會區較開闊，支線植被更密 | 選擇方向 |
| S04 BOSS | G01～G09、V01～V11、N02～N08、B01～B09 | 中央低密度，外圈高密度，保留戰鬥動線 | 遭遇、戰鬥 |

X 類光照、聲音和特效按各區需求共用，不需要每個場景重新製作。

**重要：這些是資產庫，不是每個場景都要塞滿所有物件。** 真正的自然感來自疏密變化與合理的環境分布。

## 五、Blender MCP 與 Godot 的技術規格

這部分是避免 Claude 又做出大量無法辨識、過度工整的素材。

| 項目 | 規定 |
|---|---|
| 建模單位 | 以公尺為單位 |
| Blender 原始檔 | 保留 `.blend` |
| Godot 匯入 | 優先 `.glb` |
| Mesh 原點 | 地面放置物以接地位置為基準 |
| UV | 正確展開、避免貼圖拉伸 |
| PBR 材質 | Base Color、Roughness、Normal，必要時 Metallic |
| 一般材質解析度 | 初版 1K～2K，視距離調整 |
| 主資產材質 | 視近景需求提高 |
| LOD | 樹木、巨石、大型模型需考慮遠近細節 |
| 大量植被 | Godot 使用 MultiMesh 或合適的實例化方案 |
| 地形碰撞 | 靜態三角網格碰撞 |
| 樹幹碰撞 | 簡化圓柱或膠囊近似形狀 |
| 岩石碰撞 | 簡化凸碰撞、箱體或組合形狀 |
| 草與小植物 | 原則上不需要碰撞 |
| 導航 | Godot 根據可走區域建立導航資料 |
| 模型尺度 | 必須與玩家角色及現有村莊一致 |
| 效能 | 先量測現有場景基準，再制定多邊形與 FPS 預算 |

特別提醒：若使用 `MultiMeshInstance3D` 大量生成樹木，不能假設它自動替每棵樹建立獨立碰撞。碰撞應由森林配置資料另外生成，並避免不必要的碰撞數量。

## 八、給 Claude 的執行順序與限制

雖然這份規格一次列出完整工作，但**不建議要求 Claude 一口氣做完 29 個任務，而且不做中途驗證**。

我建議分成以下交付節點：

| 交付版本 | 包含任務 | 驗收重點 |
|---|---|---|
| V0.1 白模 | T01～T09 | 先確認地形和道路好不好玩 |
| V0.2 地形 | T10～T14 | 確認碰撞、道路、材質 |
| V0.3 資產 | T15～T21 | 確認 Blender 資產品質 |
| V0.4 完整關卡 | T22～T26 | 確認森林、互動與 BOSS 功能 |
| V1.0 正式驗收 | T27～T29 | 效能、BUG 與文件 |

最重要的執行限制：

- 不得未經確認直接覆寫 `village_v2` 的場景與生成資源。
- 不得以大量基本幾何形狀冒充已完成的正式美術資產。
- 不得因為完成程式碼生成就直接宣稱場景可玩。
- Blender 資產必須在 Godot 實際匯入測試比例、材質與碰撞。
- 每個版本都要能獨立啟動測試，並記錄尚未完成的項目。

**我的建議是先讓 Claude 完成 V0.1 白模。** 因為人間之里已經有程序地形、道路和植被系統，可以優先重用成熟部分。等獸道地形和 BOSS 空間確定好玩，再讓 Blender MCP 大量製作精緻資產。

這樣不是重新從零建造一個森林，而是利用現有的幻想鄉開發基礎，建立一套可以延伸到博麗神社、迷途竹林及其他地區的自然環境資產庫。
