# JEV Decision Provider 評估（r1，2026-10-20）

範圍：只評估「JEV 從合法候選事件中挑魔理沙的下一個活動」。導航、動畫、物件預約、雙人交談、優先權、冷卻、打斷仍由既有 NpcLifeDirector／Actor 執行；JEV 不生成台詞。

## 架構（不重做系統）

- 外掛：`godot/addons/godot_jev`（AlvianEka/godot-jev 1.0.0，MIT，commit 1b232da）。**沒有啟用編輯器外掛、沒有加 autoload、沒有改 project.godot**；由 `npc_life_jev_provider.gd` 自己掛一個 client 節點。
- `systems/npc_life/npc_life_jev_provider.gd`：`mode = jev | mock`；Choice 問題；固定 `jev-1.13.0`；遊戲內不重試（max_retries 0）；決策期限 3 s。
- `npc_life_director.gd` 新增 `jev_heroes`（預設空＝全部原本決策）、`jev_mode`、`jev_timeout`、`jev_model`。流程：
  1. 原本的 `_score` 先算出合法候選（時段、冷卻、事實條件、物件可預約、對象可社交）。
  2. 有 priority ≥ 5 的反應事件 → 一律原本決策（不送 JEV）。
  3. 只剩 1 個選項 → 不送 JEV。
  4. 否則送 JEV（state＝角色身分／性格數值／興趣／關係／時段／位置／近況／所知／附近的人與其在做的事／世界狀態；options＝合法事件，社交依對象展開「marisa_chat@keine」並附距離）。
  5. 回答回來後**重新驗證合法性**（等待期間世界會變）→ 用既有 `_build_plan` 建立計畫、預約資源。
  6. 沒有金鑰／連線失敗／HTTP 錯誤／401／逾時／選項失效 → 立刻用原本權重決策（`DECIDE by=builtin_after_fallback`）。
- 金鑰：只讀環境變數 `TYPESAFE_API_KEY`／`JEV_API_KEY`。若 project setting `jev/config/api_key` 有值，provider 會拒絕使用並報錯（防止進 Git／打包）。已掃描 304 個相關檔案與 project.godot：沒有金鑰字串。

## 測試 3：正式村莊試跑（`tools/npc_life/jev_live_run.gd`，只有魔理沙用 JEV，360 s，生活時鐘 ×2）

- JEV 決策 7 次，**7/7 由既有系統執行到互動／交談並完成**：找靈夢聊天、採蘑菇、摘藥草、研究採集物 ×2、找小鈴聊天、逛市集。
- 216 s 起把端點改成連不上：下一次決策 3083 ms 逾時 → 原本決策選採蘑菇 → 正常完成；魔理沙沒有停擺。
- 288 s 起拿掉金鑰：這段時間魔理沙一直在既有事件／交談裡，沒有輪到新決策 → **村莊實跑沒驗到這段**（無金鑰退回只在測試 2 驗過）。
- 其他 HERO 照原本決策運作（同期完成：小鈴 13、阿求 5、靈夢 5、慧音 1）。
- 「找慧音」在這次村莊實跑沒出現（慧音當時在上課，上課中不接受社交）；只在測試 1 的 S3 驗過（3/3）。

## 結論與建議

- **相容性：可用。** 外掛在 4.7.2 headless 下解析、連線、Choice 回答都正常；不必啟用 autoload。注意：新增外掛後要跑一次 `--import` 更新 class 快取，否則 `JevEvaluationHandle` 等型別解析失敗。
- **穩定性：本輪 18＋7 次雲端請求 0 次伺服器錯誤**；失敗都能在期限內退回。外掛本身預設 30 s 逾時、會在 429／529 重試，遊戲內已改成 0 次重試＋director 自己的 3 s 期限。
- **品質：比原本權重決策合理**（66.7% 對 29–37%，而且更一致）：會看「誰在旁邊」「身上有沒有蘑菇」。**兩個系統性錯誤**：逛市集情境偏去找小鈴；傍晚不回家，還選 105 m 外的社交。
- **建議先不要全面套用到所有 HERO。** 先在程式端把弱點補上（例：傍晚把「回家」當硬規則或提高權重；社交距離上限），讓魔理沙單獨用 JEV 再跑一段長時間，看合理率與延遲；之後再決定要不要擴大。
