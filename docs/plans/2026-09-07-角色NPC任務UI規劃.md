## 1. 設計原則

1. **加法接上，不改既有骨架**：對話與任務只透過現有 `interact()` 契約與 signal 進來；不動 yoriichi 控制器內部。
2. **全部資料驅動**：NPC、對話、任務都是 JSON，程式只認格式。故事改動不需改 GDScript。
3. **對話中鎖操作**：進對話 → `Player.set_process_input(false)` + 相機停 + 滑鼠釋放；離開對話還原。這是唯一要碰 Player 的地方。
4. **任務 = 旗標機**：`QuestState`（autoload）維護 `flags: Dictionary`；對話節點可 `require`／`set` 旗標；任務進度只是旗標集合。不做行為樹、不做腳本語言。
5. **UI 純 Control + 程式繪製**（沿用 combat_hud 決定，避免美術債）；字型／配色先用單一主題資源 `ui/theme.tres`，之後統一換皮。
6. **NPC 視覺走 Meshy**（2026-08-26 資產裁決）；系統開發期先用 `test_npc.tscn` 量體，`visual_scene` 欄位換掉即可。

## 2. 資料格式

### 2.1 `data/<map>.npcs.json` — 每張圖的 NPC 與敵人生成點

```json
{
  "npcs": [
    { "id": "keine", "name": "上白澤慧音", "x": 232.0, "z": 105.0, "yaw": 1.57,
      "visual": "res://characters/npc/keine.tscn",
      "dialogue": "res://data/dialogue/keine.json",
      "behaviour": "stand",            // stand | wander(route) | schedule(時段位置表)
      "face_player": true }
  ],
  "enemies": [
    { "id": "fairy_1", "kind": "enemy_samurai", "x": 3.0, "z": -60.0,
      "respawn": true, "active_when": "night" }   // 旗標或時段條件
  ]
}
```

生成：`main.load_map()` 末尾加 `_spawn_npcs(meta_npcs)`，掛在 `map_root` 下（跟 portal 一樣隨圖釋放）。
`arrival_ground_y` 的教訓沿用：**xz 由使用者放，y 由射線落地**（不手填）。

### 2.2 `data/dialogue/<npc>.json` — 對話樹

```json
{
  "start": "greet",
  "nodes": {
    "greet": {
      "speaker": "上白澤慧音",
      "text": "你就是那個從神社來的劍士？",
      "require": { "not": "met_keine" },
      "set": ["met_keine"],
      "choices": [
        { "text": "是。", "next": "ask_help" },
        { "text": "……", "next": null }
      ]
    },
    "greet_again": { "speaker": "上白澤慧音", "text": "夜裡別走獸道。", "require": "met_keine", "next": null },
    "ask_help": { "speaker": "上白澤慧音", "text": "獸道的妖怪最近……", "set": ["quest.trail_youkai.start"], "next": null }
  }
}
```

規則：
- `start` 可以是陣列，依序找第一個 `require` 成立的節點（同一 NPC 依進度講不同話）。
- `require`：字串 = 旗標為真；`{"not": f}`；`{"all": [...]}`；`{"any": [...]}`。夠用，不再擴。
- `set`：旗標清單。`quest.<id>.start` / `quest.<id>.<step>` / `quest.<id>.done` 是任務系統認的命名。
- `choices` 為空且 `next` 為 null → 結束對話。

### 2.3 `data/quests.json` — 任務定義（只是旗標的「顯示層」）

```json
{
  "trail_youkai": {
    "title": "獸道上的影子",
    "steps": [
      { "flag": "quest.trail_youkai.start", "text": "前往獸道，調查夜雀屋台附近" },
      { "flag": "quest.trail_youkai.stall", "text": "回去向慧音報告" },
      { "flag": "quest.trail_youkai.done", "text": "完成" }
    ],
    "reward": { "flags": ["unlock.sun_breathing.2"] }
  }
}
```

觸發來源三種：對話 `set`、區域觸發器（`Area3D` + `flag` meta，放在 npcs.json 的 `triggers`）、敵人死亡（`enemy.died` → `enemy.<id>.killed`）。

### 2.4 存檔 `user://save.json`

`{ "flags": {...}, "map": "slice", "pos": [x,y,z], "hour": 15.7 }`。手動存（神社／人里的固定點）+ 換圖自動存。

## 3. 程式模組（新增，都是加法）

| 檔案 | 職責 | 行數估 |
|---|---|---|
| `scripts/quest_state.gd`（autoload `QuestState`） | flags 字典、`has/set/check(require)`、`flag_changed(name)` signal、存讀檔 | ~120 |
| `scripts/dialogue_runner.gd` | 載入對話 JSON、走節點、評估 require、發 `line_shown(speaker,text,choices)`／`ended` | ~150 |
| `scripts/npc_actor.gd` | 掛在 NPC 根：`get_interaction_prompt()`/`interact()` → 起 DialogueRunner；`face_player`；behaviour stand/wander/schedule | ~150 |
| `scripts/npc_spawner.gd` | `main.load_map()` 呼叫：讀 `<map>.npcs.json`，instance NPC／敵人／觸發區，射線落地 | ~100 |
| `ui/dialogue_box.tscn/.gd` | 下方對話框：名牌、逐字打字、選項列表（鍵盤／滑鼠） | ~150 |
| `ui/quest_tracker.tscn/.gd` | 右上角當前任務一行 + 目前步驟；`flag_changed` 時更新並閃一下 | ~80 |
| `ui/pause_menu.tscn/.gd` | Esc：繼續／存檔／讀檔／設定（音量、滑鼠靈敏度）／離開 | ~120 |
| `ui/quest_log.tscn/.gd` | J 鍵：任務清單（進行中／已完成） | ~100 |
| `ui/theme.tres` | 一份字型／面板色 | — |

`main.gd` 改動：`load_map()` 加一行 `_spawn_npcs()`；`_ready()` 接 `DialogueRunner` 的 signal 切鎖操作；InteractionMessage 保留給非對話物件（告示牌、物品）。

## 5. 主角相關（不動控制器）

- 對話鎖：`Player.input_locked` 一個 bool，控制器 `_physics_process` 開頭 `if input_locked: 只跑重力`。這是 yoriichi_character.gd 唯一改動（+3 行）。
- 日之呼吸解鎖：`sun_breathing.gd` 已有 data-driven slots → 加 `require_flag` 欄位，`QuestState.has()` 為假的型不進招式表。故事的「成長」就靠這條線，不做技能樹。
- 存檔位置：`QuestState.save()` 讀 `Player.global_position` 與 `DayNight` 時刻。

## 6. 分期

| 期 | 內容 | 可玩驗收 |
|---|---|---|
| **P1** | QuestState + DialogueRunner + NpcActor + dialogue_box + npcs.json spawner；一個 NPC（量體）在人里說三段話、設一個旗標 | 走到 NPC 前按 E → 對話框 → 選項 → 旗標改變 → 第二次對話換台詞 |
| P2 | quests.json + quest_tracker + 區域觸發器 + 敵人死亡旗標；串一條「人里→獸道→回報」任務 | 從接任務到完成不看程式碼能跑完 |
| P3 | pause_menu + 存讀檔 + quest_log | 關掉遊戲重開，進度還在 |
| P4 | NPC behaviour wander/schedule、Meshy NPC 模型替換、theme 換皮 | — |

P1 全部 headless 可測：`tools/verify_dialogue.gd`（載 JSON、走節點、旗標斷言）、`tools/verify_npc_spawn.gd`（載圖、NPC 數量、落地高度）。

**明確不做**：物品欄／商店／貨幣、技能樹、行為樹、語音、多語言（文字先全繁中）。

## 7. 需要使用者提供（故事填空）

動工前請填以下三張表（可以直接口述，我轉 JSON）：

**A. 角色表**
| id | 名字 | 所在圖 | 站哪（描述即可） | 作用（任務給予者／商人／路人／敵人） | 外觀來源 |
|---|---|---|---|---|---|

**B. 任務表**
| 任務 id | 標題 | 給予者 | 步驟（1、2、3…每步「去哪／做什麼」） | 完成條件 | 獎勵（解鎖哪一型／旗標） |
|---|---|---|---|---|---|

**C. 主線順序**：任務 id 的先後依賴（例：`trail_youkai` 完成才開 `shrine_night`）。

**D. 裁定項**
1. 對話鍵：沿用 E？（現在 `interact` 動作綁 E）
2. 任務日誌鍵：J？
3. 對話框樣式：和風紙張底（需貼圖）還是純半透明黑（零美術債，P1 建議）？
4. 敵人出現條件：固定生成、夜間才出、還是任務旗標控制？
