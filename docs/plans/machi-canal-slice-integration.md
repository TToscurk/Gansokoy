### 2026-09-02 補丁：水田被地形埋掉（已修，commit 07bba4a）

首輪整合後審計發現 **8/14 格水田被 `UnifiedGround` 埋住**（最深 0.63m，
田面底 −0.032 被村域緩坡從下方穿出）——此前 50m 審查圖裡「水田像硬邊
平台、田面有深色矩形」就是這個幾何穿出的視覺表現，不是貼圖問題。
根因：渠道溝槽有開挖遮罩，水田足跡沒有；原型的 `FieldGround` 在已停用的
`VillageContext` 裡，田與原始地形之間什麼都沒有。

修法（使用者裁決選 a）：`gen_terrain_river.gd` 加整平遮罩
`PADDY_FLAT_Y = −0.132`，足跡 x 288..343.5 / z −29..49，邊界 6m 緩坡，
且整平必須在渠道開挖**之前**套用（東岸帶重疊時渠道 −3.45 要贏）。
雙通道驗證：離線審計與實機 `game_eval` 一致——**14/14 格，埋入 0，
最小淨空 0.100m**；渠道三探針仍 −3.450。

審計腳本自身也犯過一次錯：首輪 `global_transform` 在脫離場景樹時是
IDENTITY，14 個探針全採樣同一點；已改用 `_world_xform()` 手動累加
transform 鏈。

## 一、為什麼是「搬進 slice」而不是「原型當主場景」

| | slice.tscn | waterway 原型 |
|---|---|---|
| 地形範圍 | **2500 × 2500m**（`R_EXT = 1250`） | 176 × 176m |
| 村域 | 半徑 300m（`VILLAGE_HALF`） | — |
| 河 | 大河 44m 寬（`WATER_HALF 22`），水面 y −5.15 | 細渠 12m 寬，水面 y 0.09 |
| 地標建築 | 鈴奈庵／鯢吞亭／霧雨店／寺子屋／龍神像／稗田邸／火見櫓 | 無 |
| 遠景 | BasinHills + `sky_panorama_lift.gdshader` 全景天空 | 無 |
| 水利設施 | 無 | 水車／堰／親水階梯／水田／木樋 |

原型是 slice 的**一個街區**，不是 slice 的替代品。

**概念圖明確要求兩者並存**（`village-concept-reference.md` L37–38）：

> 「主河在北／東北；**細渠穿行村內**（尤其東側與中央），多座木拱橋跨越，
> 渠上有**水車**。水既是灌溉與動力，也是分區邊界。」

同文件 L94 把「無農田、無村內水路」列為 slice 對概念圖的已知偏離。
原型正是補這一項。

## 三、高程

### 現況

| 原型（自成系統） | y | slice | y |
|---|---|---|---|
| 渠床 | −0.225 | 大河床 | −6.10 |
| 渠水面 | +0.090 | 大河水面 | −5.15 |
| 石岸頂 | +2.955 | 村域地面 | 約 0 ~ 4 |
| 步道頂 | +3.225 | 火見櫓 | 7.40 |
| 田面 | +3.000 | 稗田邸 | 7.15 |

### Δy = −3.0 的理由

直接搬（Δy = 0）會讓渠水面 0.09 落在村地面高度，**渠道等於沒有下切**，
變成一條浮在地上的水帶。下沉 3m 後：

| | 搬遷後 y |
|---|---|
| 石岸頂 | −0.045（≈ 村地面 0） |
| 渠水面 | −2.91 |
| 渠床 | −3.225 |
| 田面 | 0.000 |

**水力邏輯成立**：渠水面 −2.91 高於大河水面 −5.15 達 2.24m，水往大河流。

> ⚠️ Δy = −3.0 假設該處 slice 地面 y ≈ 0。**執行前必須用 raycast 或
> `_grid_height()` 實測 x=300 沿線的地形高度**，不可沿用此假設值。

- `ChannelGeometry`（15 節點）
- `VillageStoneBank`（2 段牆）

### MultiMesh 腳本：改常數而非搬節點

| 腳本 | 要改的常數 |
|---|---|

| `bank_talus.gd` | `SEGMENTS`、`BANK_FACE_X`、`WATER_LEVEL` |
| `coping_grass.gd` | `SEGMENTS`、`COPING_EDGE_X`、`BANK_TOP` |
| `bank_masonry.gd` | `SEGMENTS`、`BANK_FACE_X`、`BANK_TOP`、`WATER_LEVEL` |
| `aze_grid.gd` | `PLOT_X`、`PLOT_Z` |
| `ine_scatter.gd` | `PLOT_X`、`PLOT_Z` |

### 刪除

- **`B1_Street_Context`** — 是 slice `B1_Street` 的複製品（位移 −272），
  搬回去會與本尊重疊。
- **`VillageGround` / `FieldGround`** — 臨時地台，slice 有 `UnifiedGround`。
- **`Grove`（4 節點）** — slice 有 `VillageTrees` 與 `RiverVegetation`。
- **`ReviewCamera` / `ReviewSun` / `ReviewEnvironment`** — slice 有自己的
  `WorldEnvironment` 與全景天空 shader。

### 需要重做

- **渠道兩端收口**：目前是硬切。搬進 slice 後上游要接北／東北的大河
  分流，下游要匯回大河（見「未解問題」）。
- **渠道與地形接合**：原型的地台是平板，slice 的 `UnifiedGround` 是
  起伏地形。渠道兩岸需要開挖帶（`gen_terrain_river.gd` 的
  `APRONS` 機制可參考）。

## 五、執行順序

1. 備份 `slice.tscn`
2. **實測 x=300 沿線地形高度**，修正 Δy
3. 複驗寺子屋（314.8, 34.6）與渠道／水田的實際淨距
4. 在 slice 建 `MachiCanal` 空節點，設 transform = (300, Δy, 16.1)
5. 搬 `ChannelGeometry` / `VillageStoneBank` / `BankCaps` / `Waterworks` /
   `Openings` / `BankProps` / `PaddyFields`
6. 改五支 MultiMesh 腳本常數，重建
7. 渠道兩端收口 + 地形開挖帶
8. 三距離 ART_REVIEW（50m / 20m / 5m）+ 人眼高度 1.6m
9. Human Art Review — **只有使用者能批准**

## 六、未解問題（需使用者裁決）

### 1. 稗田邸的位置與概念圖不符

概念圖說東半農田區「其中座落一棟**華麗大宅**（＝稗田邸）」，
但 slice 的稗田邸在 **x = 233.2**，位於 B1 町家街（209.7~260.1）內，
不在東半。

三種處理：
- (a) 把水田區改放在稗田邸周圍（x 200~270），渠道改走 B1 西側或穿過街廓
- (b) 把稗田邸移到東半農田區（x ≈ 330）
- (c) 接受偏離，稗田邸留在原位，農田另置東半

### 2. 渠道要不要接大河

概念圖的細渠是灌溉系統，理應有取水口。但從北／東北大河引水到 x=300
需要拉 100m+ 的引水路線。

- (a) 完整接通：上游做取水堰，下游匯回大河
- (b) 只做下游匯流，上游淡出在村外林地
- (c) 自成系統，兩端都收在村界

### 3. 原型未完成項是否搬遷前先修

現存缺陷（見稽核）：
- 石岸只覆蓋 78m，建築沿岸 158m — **79.7m 建築臨無護岸裸河**
- `木樋_北` 軸向錯 90°、y 低 2.2m、x 偏 9m（bug）
- 石岸兩開口偏寬（14.64m / 10.78m）
- 降台石5段落差不匹配（0.59m vs 需求 0.85m）
- 碎石帶單層單排

搬進 slice 後這些缺陷仍在，且座標全變，修起來更麻煩。
**建議搬遷前先修 `木樋_北` 與石岸覆蓋範圍**。
