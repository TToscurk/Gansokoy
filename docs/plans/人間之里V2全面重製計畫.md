這份不是單純美術方向，而是把 **Godot 地形、河道、Blender 資產、設計圖、AABB、穿模、資產缺陷、風格、LOD、碰撞、驗收順序**全部串成同一套流程。

# 人間之里 V2 全面重製計畫

## 0. 專案目標

人間之里 V2 不在現有 `slice.tscn` 上繼續堆疊修改，而是在**全新的獨立場景**中重新建立。

舊版場景的用途改為：

- 劇情資料參考
- NPC / 任務 anchor 參考
- Portal 位置參考
- 可用資產來源
- 尺寸與比例參考
- 錯誤案例與效能基準

舊場景不得作為 V2 的地形基底。

V2 的目標不是單純「把舊地圖變漂亮」，而是重新建立一個：

- 空間結構合理
- 地形與建築真正融合
- 河流與河岸具有自然地貌邏輯
- 建築不浮空、不穿地
- 植被沒有底部污染
- 資產尺寸一致
- 玩家視角下具有 AAA 場景層次
- 符合幻想鄉／人間之里的視覺語言
- 可以後續持續擴充
- 在 Godot 中容易維護
- 不依賴大量不可控的一體式 Mesh

的正式版本。

---

# 1. V2 基本施工原則

整體施工順序固定為：

**設計圖 → 世界座標規劃 → 大地形 → 水系 → 道路 → 地塊 → 灰盒建築 → 正式建築 → 河岸 → 植被 → 小物 → 碰撞 → LOD / 效能 → 最終美術**

禁止反過來施工。

特別禁止：

- 先大量放房子，再修地形
- 先種樹，再挖河
- 先做河岸小物，再修改河道
- 讓房屋自帶一大片土地
- 讓樹木自帶不可拆除的土塊
- 為了修穿模直接把物件埋入地面
- 用 Scale 亂縮放資產來掩蓋尺寸錯誤
- 一次大量生成數百物件後才開始檢查
- 未驗證 AABB 就批次 Scatter
- 未驗證玩家視角就開始大量美術化

任何階段沒有通過驗收，不得直接進下一階段。

# 4. 世界尺度與座標規範

全專案採：

**1 Godot unit = 1 metre**

Blender 同樣使用：

**Unit Scale = 1.0 / Metric**

所有尺寸都必須用公尺描述。

禁止使用：

- 「放大一點」
- 「Scale 1.3 看看」
- 「差不多」
- 「感覺差不多高」

應記錄實際尺寸：

```text
建築寬：8.4 m
建築深：6.2 m
屋簷高：3.1 m
屋脊高：6.4 m
台基高：0.32 m
```

Scale 最終必須盡量維持：

```text
1, 1, 1
```

# 6. 第二階段：大地形

先做整張世界的「骨頭」。

不處理：

- 草
- 石頭
- 花
- 河岸雜物
- 建築細節

只處理：

- 高低差
- 山丘
- 河谷
- 建築平台
- 農田階差
- 道路坡度
- 世界邊界

## 地形原則

村落中心不能像程序地形一樣凹凸不平。

住宅與商業核心區應該具有人工整地痕跡。

自然坡地則可以不規則。

因此應區分：

```text
Natural Terrain
Built Terrain
Transition Terrain
```

### Natural Terrain

森林、山坡、河谷。

可以：

- 不規則
- 有侵蝕
- 有高低起伏

### Built Terrain

村莊、道路、院子、農田。

應：

- 相對平整
- 有人工修坡
- 有擋土結構
- 有清楚高程

### Transition Terrain

人工與自然交界。

使用：

- 石牆
- 土坡
- 木樁
- 草坡
- 階梯
- 排水渠

將兩者銜接。

# 7. 第三階段：河道

河道不可在建築完成之後才挖。

先確定：

- 河中心線
- 河寬
- 河深
- 水面高度
- 河床高度
- 左右岸高度
- 洪泛區
- 橋位

河流不是一條「藍色平面」。

必須包含：

```text
River Channel
River Bed
Inner Bank
Outer Bank
Flood Shelf
Revetment
Vegetation Strip
Water Surface
```

---

# 8. 河道地形設計

河流轉彎時：

外彎通常較深、岸坡較陡。

內彎通常較緩、有砂石堆積。

不要讓河道：

- 每段一樣寬
- 每段一樣深
- 左右岸完全對稱
- 每段都是相同石頭

河岸至少需要三個尺度。

### Macro

整體河谷。

### Meso

河岸坡度、砂洲、護岸。

### Micro

石頭、草、蘆葦、木樁。

---

# 9. 水面與岸線避免穿模

水面與河岸不可剛好貼在同一平面。

必須確認：

```text
Water AABB
Riverbed AABB
Bank AABB
Bridge AABB
```

不要讓：

- 河岸模型底部突然露出
- 水穿過護岸
- 水面跑到橋板上
- 河底模型高於水面
- 草漂在水上

河岸 Mesh 底部可以向下多延伸一些，以容忍 Terrain 微小差異。

---

# 10. 第四階段：道路

道路應該在正式建築前完成。

道路分：

```text
Main Street
Secondary Street
Residential Alley
Farm Road
Riverside Path
```

不同道路具有不同：

- 寬度
- 材質
- 邊界
- 排水
- 使用目的

不要所有道路全部一樣寬。

主街應具有明確視覺軸線。

巷道則應：

- 比主街窄
- 有轉折
- 有視線遮擋
- 有生活感

# 15. 底部污染規則

這是 V2 的硬規範。

## 建築

禁止：

房子下面自帶巨大土塊。

例如：

```text
[房子]
████████
████████
████████
████████ 土地
```

這會造成：

- 土塊穿 Terrain
- 材質衝突
- 地形無法調整
- 建築只能放在特定高度

建議：

```text
Building
Foundation
Optional Ground Detail
```

全部分件。

## 樹木

普通樹：

只允許：

```text
Trunk
Roots
Branches
Leaves
```

禁止：

```text
Tree + giant soil mound
```

特殊英雄景觀可以另外做：

```text
Tree_Hero_GroundCluster
```

但不能當一般 Scatter Tree 使用。

# 16. AABB 規範

每個資產進 Godot 後都要檢查 AABB。

AABB 不只是效能資料，也是資產 QA 工具。

檢查：

```text
AABB.position
AABB.size
AABB.end
```

### 建築

檢查：

- X/Y/Z 尺寸是否符合 Blender
- AABB 底部是否接近 Y=0
- 是否有異常延伸到地下
- 是否有看不到的 Mesh 拉遠 AABB

### 樹木

例如一棵 12m 高的樹：

正常：

```text
Y min ≈ 0
Y max ≈ 12
```

如果：

```text
Y min = -4.7
```

代表很可能有：

- 土塊
- 隱藏 vertex
- stray geometry
- root contamination

需要退回 Blender。

---

# 17. AABB 底部污染自動檢查

可以對每個資產建立自動 QA。

例如：

```text
asset_bottom = aabb.position.y
```

依類別判斷。

普通樹：

```text
bottom tolerance ≈ -0.1 ~ -0.3m
```

房屋：

根據 Foundation 規格。

如果一個普通建築底部：

```text
-3.8m
```

但看起來只是普通町家，

直接標記：

`ASSET_BOTTOM_CONTAMINATION`

---

# 18. AABB 側向污染

同樣檢查 X / Z。

如果一棟 8m 房屋：

視覺約：

```text
8 × 7 m
```

但 AABB：

```text
28 × 7 × 30 m
```

代表可能存在：

- stray vertices
- 隱藏物件
- 土地平面
- 遺留 geometry
- 裝飾被錯誤 join

不得進正式場景。

---

# 19. Pivot / Origin 規格

建築：

Origin 優先放：

**底部中心**

樹：

Origin：

**樹幹與地面接觸中心**

石頭：

Origin：

**底部中心或質量中心附近**

橋：

依 modular placement 規格固定。

禁止 Origin：

- 距模型幾十公尺
- 位於世界原點而不是資產
- 在屋頂
- 在無關的土塊

---

# 20. Transform 規格

Blender export 前：

```text
Location 合理
Rotation = 0
Scale = 1
```

使用 Apply Transform。

Godot 裡正式資產盡量：

```text
Scale = Vector3(1,1,1)
```

小幅調整可以接受。

禁止用：

```text
0.37
2.8
0.53
```

這種極端非均勻縮放長期補救錯誤模型。

---

# 21. Mesh 缺陷檢查

Blender QA 必須檢查：

- non-manifold
- flipped normals
- duplicate vertices
- floating geometry
- hidden geometry
- intersecting geometry
- zero-area faces
- internal faces
- impossible thin geometry

尤其 AI 生成資產常見：

- 屋頂與牆焊在一起
- 看似門窗但其實是一坨面
- 房子內部有奇怪肉塊
- 背面出現多餘結構
- 底下形成巨大封閉 Mesh

全部需要修。

---

# 22. AI / Tripo / Meshy 資產規則

AI 生成結果一律視為：

**Raw Asset**

不是 Finished Asset。

流程：

```text
AI Generation
↓
Blender Inspection
↓
Geometry Cleanup
↓
Separate Parts
↓
Material Cleanup
↓
Pivot
↓
AABB Check
↓
LOD
↓
Collision
↓
Godot Import
```

AI 做完不可直接批量放進地圖。

# 23. 建築風格

整體目標不是「純寫實江戶村」。

核心應為：

**幻想鄉式日式村落 + 手工感 + 東方 Project 世界觀 + 高品質遊戲環境**

應該讓玩家感覺：

「這是幻想鄉的人間之里。」

而不是：

「這是下載的日本町家素材包。」

---

# 24. 風格語言

主要視覺：

- 木
- 土
- 石
- 灰瓦
- 米白牆
- 深棕木構
- 少量紅色
- 布簾
- 招牌
- 紙燈籠
- 不完全筆直的道路
- 自然植被侵入人工環境

不要：

- 全部超乾淨
- 建築完全等距排列
- 所有屋頂一模一樣
- 每棟房子同材質
- 現代日式觀光街風格

---

# 25. AAA 不等於超寫實

本專案的 AAA 指：

- 資產比例正確
- 材質層次好
- 空間構圖好
- 光影好
- silhouette 好
- 細節密度合理
- 玩家近距離看不穿幫
- 遠距離仍有漂亮輪廓

不是：

每個 Mesh 都幾百萬面。

目前已經看到町家單棟可能 30～100 萬面。

這不是 AAA 的必要條件。

好的遊戲資產應把面數花在：

- Silhouette
- Roof curve
- Hero details
- Close-up features

不是隱藏面。

---

# 26. 材質規格

每個主要材質應至少考慮：

```text
Base Color
Normal
Roughness
AO
```

避免：

- 完全平滑木頭
- 所有瓦片一樣反光
- 土地像塑膠
- 石頭像水泥球
- 所有材質 roughness 一致

木構需要：

- 年代感
- 色差
- 方向
- roughness variation

# 29. 植被設計

先做：

### Large Vegetation

- 大樹
- 竹林
- 林帶

再：

### Medium

- 灌木
- 蘆葦
- 大草叢

最後：

### Small

- 草
- 花
- 地被

不要反過來。

大樹決定構圖。

小草只補細節。

---

# 30. 植被接地檢查

每棵樹都要：

- 接地
- 不浮空
- 不過度埋入
- 根部方向合理

Scatter 前先驗證來源資產 AABB。

如果 source tree 有土塊污染，

**禁止 Scatter。**

否則會變成幾百個土球散落整張地圖。

---

# 31. 建築接地方法

不能單純讓房屋深入 Terrain 0.5m。

應：

1. 整理 Parcel
2. 放 Foundation
3. 放 Building
4. 處理 Road transition
5. 加 Steps / Ramp
6. 最後才修 Terrain

這樣能避免：

「看起來站住了，其實半棟埋在地下。」

---

# 32. 自動穿模檢查

V2 建議建立 Debug 工具。

至少檢查：

```text
Building vs Terrain
Building vs Building
Tree vs Building
Tree vs Road
Prop vs Road
Bridge vs Riverbank
Bridge vs Water
```

AABB 可以作第一層 broad-phase。

如果：

```text
AABB.intersects(other_aabb)
```

再進一步檢查。

AABB intersection 不代表一定穿模，

但可以快速找出可疑物件。

---

# 33. 地表穿透檢查

對建築 footprint 取多個 sample point。

向下 Raycast。

比較：

```text
building_bottom_y
terrain_y
```

如果差值超過 tolerance：

### 正值太大

浮空。

### 負值太大

穿地。

允許 tolerance 例如：

```text
±0.05 ~ 0.15 m
```

依資產類型設定。

---

# 34. 建築彼此距離

不要只測 Mesh 是否 intersect。

還要保留 Gameplay Clearance。

例如：

```text
Building Clearance
NPC Clearance
Player Clearance
Camera Clearance
```

第三人稱遊戲尤其要注意 Camera。

一條玩家走得過去的 1m 巷子，

不代表第三人稱攝影機也能正常運作。

---

# 35. 玩家視角驗收

每完成一個區域必須從：

### Eye Level

第三人稱正常高度。

### Street Level

主街方向。

### Reverse View

回頭看。

### Elevated View

略高位置。

### Top Down

俯視。

檢查。

不能只用 Editor 俯視圖判斷品質。

---

# 36. 視覺焦點

主要視覺節點建議：

- 南入口大鳥居
- 主街
- 龍神像／橋
- 北丘
- 稗田邸
- 寺子屋
- 鈴奈庵
- 鯢吞亭

玩家每走一段路應該有下一個視覺吸引物。

避免：

走 100m 都只是同樣房子。

---

# 37. 主街設計

主街不能像「超寬空廣場」。

建築高度與街寬要產生合理比例。

街道兩側可加入：

- 招牌
- 屋簷
- 布簾
- 箱子
- 水桶
- 小攤
- 木板
- 小植栽

但先確保基本空間比例正確。

---

# 38. 市集

市集不能只有建築。

需要生活資訊。

例如：

- 攤架
- 布棚
- 籃子
- 木箱
- 桶
- 蔬菜
- 布
- 陶器
- 食品
- 掛旗

但不得大量複製完全相同的 prop cluster。

---

# 39. 農田

農田不是平面貼圖。

需要：

```text
Field Shape
Bund
Irrigation
Path
Water
Crop
Farm Props
```

田埂要明確。

水渠與河道應具有邏輯關係。

---

# 40. 北丘與遠景

北丘是重要的 vertical landmark。

用途：

- 阻止世界看起來無限延伸
- 建立村落方向感
- 提供主街視覺終點
- 建立幻想鄉層次

遠山不需要大量 polygon。

主要靠：

- silhouette
- fog
- lighting
- vegetation mass

---

# 41. LOD

重要模型建立：

```text
LOD0
LOD1
LOD2
LOD3 / Impostor
```

LOD0：

玩家近距離。

LOD1：

中距離。

LOD2：

遠距離。

不要讓 100 萬面的房屋在 150m 外仍然全尺寸渲染。

---

# 42. Collision

禁止重要高模直接：

`Create Trimesh Collision`

作為唯一方案。

建築碰撞應使用：

- Box
- Convex
- Simple Mesh

只有真正複雜形狀才使用精細 collision。

樹木通常只需要：

```text
Capsule / Cylinder
```

---

# 43. 效能目標

目前舊版已經存在很高的 visible triangle 數，因此 V2 必須在建構期間就控制成本。

建議 V2 初步目標：

```text
Visible triangles <= 6 million
```

這是工程目標，不是永遠不可突破的硬上限。

同時追蹤：

- draw calls
- shadow triangles
- VRAM
- node count
- load time
- frame time

---

# 44. 傳送效能

舊場景目前已經有 loading overlay 修正。

V2 的真正目標應是：

```text
Trail → Village
<= 3 seconds
```

理想：

```text
< 2 seconds
```

不能只靠 Loading Screen 掩蓋 10 秒。

# 48. 自動拒絕條件

遇到以下任一問題，Asset 不得放進正式 V2：

```text
AABB 異常
底部污染
Pivot 錯誤
Scale 未 Apply
翻面
大量隱藏 Mesh
嚴重 non-manifold
材質缺失
高度與規格不符
高模無 LOD
房屋與土地焊死
樹木自帶巨大土塊
Collision 過重
```

標記：

`ASSET_REJECTED`

修復後重新檢查。

# 49. Blender AI 工作方式

AI 操作 Blender 時應遵守：

先檢查，再修改。

每個 Asset 的流程：

```text
Import
→ Inspect
→ Measure
→ AABB
→ Geometry Audit
→ Bottom Audit
→ Separate
→ Cleanup
→ Materials
→ LOD
→ Collision
→ Export
→ Godot Verification
```

禁止：

```text
Import
→ Export
```

---

# 50. Godot AI 工作方式

Godot 部分優先透過 MCP / Editor 真實狀態驗證。

不能只修改 `.tscn` 然後假設正確。

每一輪：

```text
Edit
→ Load Scene
→ Inspect
→ F5/F6
→ Player Walk
→ Screenshot
→ Fix
```

如果 AI 能直接透過 MCP 看結果，

優先讓它使用雙向回饋。

負責：

- Mesh
- UV

- Geometry cleanup
- LOD
- Collision source

### Godot

- Navigation

- Environment

# 54. 最重要的施工紀律

整個 V2 必須一直遵守：

> **先解決空間，再解決資產；先解決大形，再解決細節；先解決接地，再解決裝飾；先驗證，再批量生成。**

如果一棟房子的位置、地基、尺寸還不正確，

不要替它放燈籠。

如果河道還會改，

不要替它種蘆葦。

如果 Terrain 還沒定，

不要大量種樹。

如果 AABB 還沒檢，

不要 Scatter。

如果 Greybox 還沒通過，

不要開始大量 Blender 正式資產。
