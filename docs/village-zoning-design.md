## 0. 這一輪要解決的問題

使用者的原話：「**村子在做密度不一樣的街區 不要混在一起**」。

先把現況量清楚，不要憑印象改：

**所以「村子看起來很空」不是建蔽率太低，是三件別的事：**

1. **每個街區長得一模一樣。** 34 個院落用同一組參數：同樣的 0.86 有房機率、

3. **中庭是空的。** 蔵 0.6 機率、離れ 2 個各 0.55 機率，其餘就是一片土。

換句話說：**問題是「均質」，不是「稀疏」。** 這一輪要做的是把 42 個街區
分成三種**性格明確**的區，區與區之間不混。

## 2. 街道收窄

現況（`PATH_SEGMENTS.width`）與遮罩淡出（`w*0.5 + 2.0`）合起來，
實際看到的鋪面帶 ≈ `width + 4`：

| 街 | 現在 width | 實際鋪面 | v14 width | v14 鋪面 |
|---|---|---|---|---|
| 本通 | 11.0 | ~15 m | **8.0** | ~9.8 m |
| 橫町 | 9.0 | ~13 m | **7.0** | ~8.8 m |
| 其餘南北／東西街 | 7.0 | ~11 m | **4.5** | ~6.3 m |
| 水路旁 | 7.5 | ~11.5 m | **5.0** | ~6.8 m |
| 西南門引道 | 5.2 | ~9 m | 4.0 | ~5.8 m |

遮罩淡出同時改成 `w*0.5 + 0.9`。

**⚠ 這裡有個結構問題要決定：**
街區骨架的間距是 52 m（x）、55 m（z），街區 42×45，
所以**牆到牆的淨距是 10.8 m**。街道收到 4.5 m 之後，兩側各留 3.15 m 的空地。
那條空地會變成一圈沒有用途的土帶，看起來像「路旁的荒地」。

三個選項（→ 問答第 3 題）：

- **(A) 把街區加大**：`BLOCK_W 42→46`、`BLOCK_D 45→49`，牆到牆剩 6.8 m，
  4.5 m 巷道兩側各留 1.15 m。缺點：地標街區（稗田邸、市集、寺子屋…）
  的內容都是照 42×45 排的，要一起重算。
- **(B) 保留空地，但填滿它**：兩側做側溝（石溝）、生垣、電柱級的常夜燈、
  堆放的柴薪。等於把 3 m 的空地當成「街緣」來設計。
- **(C) 只收主街，巷道維持 7 m**：改動最小，但「巷道 3~4 m」這個決定就沒實現。

## 3. 樹

### 3.1 現在為什麼難看

`make_trees.py` 的 `tree_round`：

```python
objs = [add_trunk(h, 0.30, 0.16, seed=seed)]      # 樹幹：一根圓錐，直上直下
tiers = [(h + 0.1, 1.55*spread, 2, ...), ...]      # 樹冠：icosphere subdivisions=1
d = rad * 0.55                                     # 兩顆樹冠往兩側各偏 0.85 m
```

三個具體缺陷：

1. **樹幹頂端裸露。** 最低一層是兩顆球、各往外偏 0.85 m，**軸線上沒有東西**。
   樹幹直直插上去，頂端那一截 0.9 m 就這樣露在外面 —— 就是截圖裡的「縫」。
2. **沒有枝。** 樹幹是一根圓錐直接頂到樹冠，中間沒有分枝，
   剪影是「棒棒糖」而不是「樹」。
3. **`subdivisions=1` 的 icosphere = 80 個面**，flat shading 之後
   每個面都是一大塊色 —— 近看是低模球，跟旁邊寫實 PBR 的建築材質打架。

### 3.2 改法

| 項目 | 改法 |
|---|---|
| 分枝 | 主幹在 `0.58h` 分出 3~4 根枝（用 `strut` 式的端點掃掠），枝端才掛樹冠 |
| 包住接點 | 最低一層樹冠**必須有一顆在軸線上**，且中心 z ≤ 分枝點 + 0.3 |
| 面數 | `subdivisions=1 → 2`（80 → 320 面），維持 flat shading 的塊面感 |
| 裙邊 | 樹冠底部加一圈向下垂的環（葉子是往下垂的，不是球的下半） |
| 樹種依區 | 町方＝柿・松（少量、修剪過）／半農＝欅・榎／在＝杉・大欅／水路＝柳 |

樹是 MultiMesh 散佈的，改 glb 不影響產生器結構，重跑就換掉。

## 8. v15：貼圖生成 + 使用者第二輪回饋

### 8.1 「素材很單調」的真正原因

`manifest.json` 登記了 **25 組**貼圖，但 `assets/textures/` 裡**只有 11 組**真的存在。
缺的那 14 組（`roof_thatch`、`wood_frame`、`tatami`、`stone_path`…）
一律被 `pbr()` 退化成純色 —— 而且**茅葺屋頂當時借的是 `terrain_grass`**（空拍草地貼圖），
難怪茅頂看起來像鋪了草皮。

補不回來：Poly Haven 被這個環境的網路政策擋掉（`CONNECT 403`），numpy 也是壞的。
所以寫了 `tools/gen_textures.gd`：**用 Godot 內建 `Image` 程序化烤貼圖**，零依賴。

| 新貼圖組 | 用在哪 |
|---|---|
| `roof_thatch` | 茅葺屋頂（終於不是草皮了） |
| `namako` | 土藏的海鼠壁（菱格黑瓦 + 凸白目地） |
| `pebble` | 玉石／州濱 |
| `foliage` | 生垣的葉團 |
| `wood_lattice` | 格子窗 |
| `stone_flag` | 板石鋪面 |
| `shoji` | 障子 |
| `tatami` | 疊蓆（室內用） |

做法：可平舖的 value-noise（格點先隨機好再雙線性取樣，週期整除 → 天生無縫）
+ 每種材質自己的圖案函式（Worley 做玉石與葉團、45° 旋轉做菱格…），
高度場再用中央差分轉法線。384×384，8 組 12 秒。

**要改樣式就改 `gen_textures.gd`，不要手動編輯 jpg。**

### 8.2 「牆擋到窗戶」的真兇：下屋

不是圍牆，是**建物自己的下屋（披屋）**：

```gdscript
var sgn_g := 1.0 if lib.rand() < 0.5 else -1.0     # ← 這裡
```

本地 +z 是立面（格子窗、玄關、庇都在那邊），但下屋往哪一側是**擲骰子決定**的 ——
一半的長屋在自己的窗前 1.5~2.3m 立了一道牆。

**門面淨空檢查抓不到它**：那支檢查比對的是「別人的地權有沒有壓到我的門面」，
而下屋是**同一棟建物自己的**構件。改成 `sgn_g := -1.0`（只能往背面長）。

兩次的病根是同一個：**光滑的封閉曲面**。真正的樹籬輪廓是碎的 ——
幾百片小葉戳出來，逆光時邊緣是毛的。光滑曲面不管貼什麼圖都是水果。
cellular 花紋投影到橢圓球上，那就是西瓜皮。

### 9.1 新做法

`godot/assets/blender/make_hedge.py`，三個變體（密實／高散／矮寬）：

1. **粗胚塊體**：上緣渾圓、側面近垂直的長塊，顏色壓到接近黑綠。
   它的工作只是**擋住視線** —— 看得到殼就是葉子撒得不夠。
2. **~1800 叢小葉**：每叢 5 片短而寬的雙面三角形，沿殼的外法線長出去，
   葉根埋進殼裡 7.5cm。這層才是輪廓變碎的原因。
3. **底下露枝幹**：樹籬不是浮在地上的。

一個模組 ~2.2 萬個三角形，沿生垣線每 2.4m 擺一個，
全村 322 個 → 走 **MultiMesh**（每種變體一次 draw call）。

### 9.2 這一輪踩到的坑（四個，都是自己種的）

1. **Blender 是 Z-up，我用 Y-up 建模。** 再加上 `export_yup=True` 又轉一次，
   整條樹籬是**躺著**的 —— 在 Godot 裡看到的是它的底面（法線朝內 → 全黑）、
   枝葉全擠在一條邊上、枝幹變成水平的棒子。
   `make_props.py` 是照 Blender 原生 Z-up 寫的，這支一開始沒跟。
2. **鏡射面沒反繞序。** `sd=-1` 那半邊法線指進樹籬內部，整片背光成黑色。
   材質開 `CULL_DISABLED` 沒有用 —— 那只讓背面**畫得出來**，
   照明用的還是原本的法線。葉子是薄片，正反要各給一張自己的面。
3. **殼與枝葉用了兩份略有出入的曲面公式**，枝葉撒不到殼的側面，
   留下大片光滑的殼。改成共用同一個 `make_surf()`。
4. **glTF 的 COLOR_0 不做色彩空間轉換。** 照 sRGB 直覺填的顏色
   在引擎裡當線性讀，暗得像墨綠塑膠。（量過 buffer 才確定，不是猜的。）

### 9.3 順手補的工具

`tools/shots/*.json` 的每一張正面照現在可以指定 `"time"`。
ADR-016 要求每張都親眼看過，但預設的 17:5x 斜陽會把半數畫面壓進陰影裡 ——
要檢查造型的鏡頭寫 `"time": 11` 就好。

### 9.4 環境備忘

- **Blender MCP 這個 session 沒有**（連上的只有 github / chrome-devtools /
  Higgsfield / Google Drive / Notion）。但 `/usr/bin/blender` 4.0.2 本來就在，
  而且 CLI 腳本比 MCP 適合這個專案：跟著 git 走、可重跑。
- Blender 在這台機器上 **EEVEE 不能用**（缺 libEGL），預覽要用
  `CYCLES` + `device='CPU'` + `use_denoising=False`（沒有 OpenImageDenoiser）。
